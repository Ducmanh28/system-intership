# Mạng Định nghĩa bằng Phần mềm (SDN — Software-Defined Networking)

**SDN (Software-Defined Networking)** là kiến trúc mạng hiện đại giải quyết những giới hạn cố hữu của hạ tầng mạng truyền thống bằng cách **tách rời mặt phẳng điều khiển (Control Plane) khỏi mặt phẳng chuyển tiếp dữ liệu (Data Plane)**, tập trung hóa trí thông minh mạng vào một bộ điều khiển phần mềm và mở ra khả năng **lập trình hóa toàn bộ hạ tầng mạng (Network Programmability)** thông qua các giao diện API chuẩn.

## 1. Tại sao cần SDN? Giới hạn của Mạng Truyền thống

Trong kiến trúc mạng truyền thống, mỗi thiết bị Switch hoặc Router là một thực thể độc lập, đóng gói chặt chẽ cả 3 thành phần bên trong một hộp phần cứng duy nhất:
* **Data Plane (ASIC):** Xử lý chuyển tiếp gói tin.
* **Control Plane (OS/CPU):** Chạy các giao thức phân tán (STP, OSPF, BGP...) để tự tính toán đường đi.
* **Management Plane (CLI/SNMP):** Giao diện cấu hình thủ công từng thiết bị (*Box-by-Box*).

**Hệ quả khi vận hành hạ tầng quy mô lớn (Data Center, Cloud, ISP):**
1. **Cấu hình thủ công & Dễ lỗi:** Muốn thay đổi một chính sách VLAN, ACL hoặc QoS trên 500 Switch, kỹ sư phải đăng nhập vào từng thiết bị hoặc viết script rời rạc.
2. **Thiếu cái nhìn toàn cảnh (No Global View):** Mỗi Router chỉ nhìn thấy các hàng xóm lân cận, dẫn đến việc tối ưu hóa lưu lượng toàn cục (Traffic Engineering) cực kỳ phức tạp.
3. **Độc quyền phần cứng (Vendor Lock-in):** Phần mềm điều khiển gắn chặt với chip phần cứng của từng hãng, khó tùy biến tính năng mới theo nhu cầu nghiệp vụ.
4. **Hạn chế ảo hóa & Cloud:** Giới hạn $4096$ VLAN (12-bit) và cơ chế chống lặp STP khóa cổng dự phòng không đáp ứng được môi trường Multi-tenant (đa khách hàng) và di chuyển máy ảo (VM Live Migration) linh hoạt.

## 2. Kiến trúc 3 Tầng của SDN (SDN Architecture)

Kiến trúc SDN chuẩn (theo định nghĩa của **ONF — Open Networking Foundation**) chia hệ thống mạng thành **3 tầng chức năng** giao tiếp với nhau qua **3 nhóm giao diện (API)**:

```text
+-----------------------------------------------------------------------+
|  APPLICATION PLANE (Tầng Ứng dụng Mạng)                               |
|  [Traffic Engineering]  [Firewall/IDS]  [Load Balancer]  [Monitoring] |
+-----------------------------------+-----------------------------------+
                                    |  <-- Northbound API (REST, gRPC)
+-----------------------------------v-----------------------------------+
|  CONTROL PLANE (SDN Controller - "Bộ não" tập trung)                  |
|  [Topology Manager]  [Routing Engine]  [Flow Programmer]  [State DB]  | <==> East/West API
+-----------------------------------+-----------------------------------+      (HA Cluster)
                                    |  <-- Southbound API (OpenFlow,
+-----------------------------------v---+  NETCONF/YANG, OVSDB, P4)
|  DATA PLANE (Tầng Hạ tầng Chuyển tiếp)                                |
|  [White-box Switches]   [Open vSwitch (OVS)]   [SmartNICs / DPUs]     |
+-----------------------------------------------------------------------+
```

### 2.1. Tầng Hạ tầng — Data Plane (Infrastructure Layer)
* Bao gồm các thiết bị chuyển mạch vật lý (Switch trắng — **White-box Switch** dùng chip Broadcom Trident/Tomahawk) và thiết bị chuyển mạch ảo (**Open vSwitch — OVS** chạy trên Hypervisor/Linux).
* Thiết bị Data Plane trong SDN được tinh giản tối đa: **không tự chạy OSPF hay STP**, chỉ đóng vai trò là các "cỗ máy chuyển tiếp siêu tốc" (*Dumb/Fast Forwarding Devices*), tuân thủ tuyệt đối các luật chuyển tiếp do Controller nạp xuống.

### 2.2. Tầng Điều khiển — Control Plane (SDN Controller)
* Là "bộ não" trung tâm của toàn mạng (ví dụ: **OpenDaylight, ONOS, Ryu, Cisco APIC, VMware NSX Manager**).
* **Chức năng cốt lõi:**
  * Thu thập trạng thái từ toàn bộ thiết bị Data Plane để dựng lên một **bản đồ mạng toàn cục duy nhất (Global Network Topology & State)** trong bộ nhớ.
  * Tính toán đường đi tối ưu, thực thi chính sách bảo mật và biên dịch thành các luật chuyển tiếp (Flow Rules) đẩy ngược xuống các Switch.
* **Tính sẵn sàng cao (High Availability):** Trong thực tế, SDN Controller không chạy đơn lẻ (tránh *Single Point of Failure*) mà triển khai theo cụm phân tán (**Cluster 3 hoặc 5 nodes** dùng thuật toán đồng thuận Raft/Paxos).

### 2.3. Tầng Ứng dụng — Application Plane
* Là các phần mềm nghiệp vụ mạng chạy phía trên Controller (định tuyến, cân bằng tải, tường lửa phân tán, phát hiện DDoS, tự động hóa mạng).
* Nhờ nhìn thấy toàn bộ mạng như một "chiếc Switch khổng lồ duy nhất" (*One Big Switch abstraction*), ứng dụng chỉ cần ra lệnh logic mức cao (ví dụ: *"Cấm nhóm VM Web truy cập trực tiếp vào nhóm VM Database"*), Controller sẽ tự tính toán và cài luật xuống đúng các Switch liên quan.

### 2.4. Các Giao diện Giao tiếp (SDN APIs)
1. **Southbound API (SBI):** Giao diện giữa Controller và thiết bị Data Plane.
   * **OpenFlow:** Giao thức chuẩn mở đầu tiên cho phép Controller thao tác trực tiếp vào bảng Flow của Switch.
   * **NETCONF / RESTCONF + YANG:** Chuẩn hiện đại dùng mô hình dữ liệu YANG để cấu hình thiết bị mạng tự động thay thế CLI/SNMP.
   * **OVSDB (Open vSwitch Database):** Giao thức quản lý cấu hình cổng, bridge và tunnel trên Open vSwitch.
   * **P4Runtime:** Giao diện lập trình mặt phẳng dữ liệu thế hệ mới.
2. **Northbound API (NBI):** Giao diện giữa Controller và Application Plane, thường sử dụng **RESTful API (JSON/HTTP)** hoặc **gRPC**, giúp lập trình viên điều khiển mạng bằng Python, Go, Java như một dịch vụ phần mềm.
3. **East–Westbound API:** Giao diện giao tiếp ngang hàng dùng để đồng bộ trạng thái giữa các node trong cụm SDN Controller HA hoặc liên kết giữa nhiều miền SDN khác nhau (Multi-domain SDN).

## 3. Cơ chế Hoạt động Cốt lõi: OpenFlow & Flow Tables

Giao thức **OpenFlow** mô hình hóa hoạt động xử lý gói tin bên trong Switch thành một chuỗi các bảng luồng nối tiếp nhau (**Flow Table Pipeline**) lưu trên chip nhớ **TCAM**.

### 3.1. Cấu trúc một dòng luật (Flow Entry)
Mỗi Flow Entry trong Flow Table gồm 6 thành phần chính:

| Thành phần | Chức năng kỹ thuật |
| :--- | :--- |
| **Match Fields** | Điều kiện so khớp tiêu đề gói tin: Cổng vào (`Ingress Port`), `Src/Dst MAC`, `VLAN ID`, `Src/Dst IP`, `Protocol`, `TCP/UDP Port`... |
| **Priority** | Độ ưu tiên xử lý (số càng lớn càng ưu tiên). Nếu gói tin khớp nhiều luật, luật có Priority cao nhất được áp dụng. |
| **Counters** | Bộ đếm thống kê số lượng gói tin (`Packet Count`) và dung lượng (`Byte Count`) đã khớp luật này (phục vụ giám sát thời gian thực). |
| **Instructions / Actions** | Hành động thực thi: Đẩy ra cổng cụ thể (`Output: Port X`), Hủy gói (`Drop`), Sửa tiêu đề (`Modify-Field` — dùng cho NAT/VLAN), hoặc Đẩy lên Controller (`Controller`). |
| **Timeouts** | Thời gian sống của luật: `Idle Timeout` (xóa luật nếu không có gói nào khớp trong $X$ giây) và `Hard Timeout` (xóa luật tuyệt đối sau $Y$ giây). |
| **Cookie** | Giá trị định danh nội bộ do Controller gắn vào để dễ dàng lọc, thống kê hoặc xóa nhóm luật. |

### 3.2. Hai chế độ nạp luật: Reactive vs Proactive

1. **Chế độ Phản ứng (Reactive Mode):**
   * Khi gói tin đầu tiên của một luồng mới đi vào Switch và không khớp bất kỳ luật nào trong Flow Table (**Table-Miss**), Switch đóng gói phần đầu gói tin vào bản tin **`Packet-In`** gửi lên SDN Controller.
   * Controller phân tích gói tin, tính toán đường đi dựa trên bản đồ toàn cục, sau đó gửi bản tin **`Flow-Mod`** xuống tất cả các Switch trên tuyến đường để cài đặt Flow Entry mới, đồng thời gửi **`Packet-Out`** để đẩy gói tin đầu tiên đi tiếp. Các gói tin tiếp theo của luồng này sẽ chạy thẳng qua phần cứng với độ trễ bằng $0$ mà không cần hỏi lại Controller.
   * *Nhược điểm:* Gói tin đầu tiên bị trễ (*First-packet latency*) và Controller dễ bị quá tải nếu gặp tấn công quét port hoặc DDoS tạo hàng triệu luồng giả.

2. **Chế độ Chủ động (Proactive Mode):**
   * Controller tính toán trước toàn bộ đường đi và cài sẵn các Flow Entry xuống Switch **trước khi lưu lượng xuất hiện**.
   * *Ưu điểm:* Loại bỏ hoàn toàn độ trễ `Packet-In`, đạt hiệu năng và độ ổn định cao nhất — đây là mô hình tiêu chuẩn được sử dụng trong các Data Center lớn hiện nay.

## 4. Kiến trúc Mạng Overlay & Underlay trong SDN

Trong các Data Center hiện đại và hạ tầng Cloud (OpenStack, VMware NSX, Cisco ACI), SDN giải quyết bài toán ảo hóa mạng bằng mô hình phân tách **Underlay** và **Overlay**:

```text
===========================================================================
  OVERLAY NETWORK (Mạng Ảo - VXLAN Tunneling + BGP EVPN Control Plane)
  [VM-1: 10.10.1.5] <========== VXLAN Tunnel (VNI 5001) ==========> [VM-2: 10.10.1.6]
        |                                                                 |
  [VTEP 1: 192.168.100.1]                                         [VTEP 2: 192.168.100.2]
===========================================================================
        |                                                                 |
        +------> [Leaf Switch 1] ---> [Spine Switch] ---> [Leaf Switch 2] +
  UNDERLAY NETWORK (Hạ tầng Vật lý IP L3 thuần túy - Spine-Leaf + ECMP)
===========================================================================
```

### 4.1. Mạng Underlay (Hạ tầng Vận chuyển Vật lý)
* Là mạng vật lý nền tảng gồm các Switch kết nối theo kiến trúc **Spine–Leaf (Clos Topology)**.
* Chạy định tuyến Tầng 3 thuần túy (OSPF hoặc eBGP) với cơ chế **ECMP (Equal-Cost Multi-Path)** để tận dụng $100\%$ băng thông mọi đường cáp và loại bỏ hoàn toàn giao thức STP.
* Nhiệm vụ duy nhất của Underlay là đảm bảo kết nối IP thông suốt, độ trễ thấp giữa các thiết bị đầu cuối đường hầm (**VTEP**).

### 4.2. Mạng Overlay (Mạng Ảo hóa Logic)
* Là mạng ảo chạy chồng lên trên hạ tầng Underlay bằng kỹ thuật đóng gói gói tin trong gói tin (**Tunneling / Encapsulation**).
* **Giao thức VXLAN (Virtual Extensible LAN — RFC 7348):**
  * Đóng gói toàn bộ Ethernet Frame của máy ảo (Layer 2) vào bên trong một gói tin **UDP** của mạng vật lý (Layer 3) — gọi là kỹ thuật **MAC-in-UDP** (sử dụng **UDP Port `4789`**).
  * Sử dụng trường **VNI (VXLAN Network Identifier)** dài **24-bit**, mở rộng số lượng phân đoạn mạng độc lập từ $4,096$ (của VLAN 12-bit) lên tới **$16,777,216$ ($16.7\text{ triệu}$)** mạng ảo.
  * Cho phép mở rộng miền Layer 2 xuyên qua hạ tầng Layer 3 (L2-over-L3), giúp máy ảo di chuyển tự do giữa các tủ Rack khác nhau mà vẫn giữ nguyên địa chỉ IP và MAC.
* **VTEP (VXLAN Tunnel Endpoint):** Thiết bị thực hiện việc đóng gói và mở gói VXLAN (có thể là Switch Leaf phần cứng hoặc Open vSwitch ngay bên trong máy chủ Hypervisor).
* **BGP EVPN (Ethernet VPN):** Đóng vai trò là Control Plane hiện đại cho VXLAN, cho phép các VTEP tự động quảng bá thông tin địa chỉ MAC và IP của máy ảo cho nhau qua BGP, loại bỏ cơ chế học MAC bằng Flood-and-Learn kém hiệu quả.

## 5. Ứng dụng Thực tế & Hệ sinh thái SDN Hiện đại

| Lĩnh vực ứng dụng | Công nghệ / Giải pháp tiêu biểu | Cơ chế & Giá trị mang lại |
| :--- | :--- | :--- |
| **Data Center SDN** | **Cisco ACI, VMware NSX, Arista CloudVision, SONiC** | Tự động hóa triển khai mạng cho hàng nghìn máy chủ, phân mảnh vi mô (**Micro-segmentation** — áp đặt Firewall tới từng card mạng của từng VM), tự động hóa cân bằng tải. |
| **SD-WAN** *(Mạng diện rộng)* | **Cisco Catalyst SD-WAN (Viptela), Fortinet Secure SD-WAN, VMware VeloCloud** | Tách Control Plane khỏi các Router chi nhánh. Tự động đo chất lượng đường truyền (Latency, Jitter, Packet Loss) để lái lưu lượng quan trọng (Voice/Video) sang đường tốt nhất (**Application-Aware Routing**), kết hợp đồng thời MPLS + Internet + 5G và triển khai không chạm (**ZTP**). |
| **Cloud Native & Kubernetes** | **Cilium (eBPF), Calico, Flannel, OVN-Kubernetes** | Áp dụng nguyên lý SDN cho Container: tự động cấp phát IP, định tuyến giữa các Pod xuyên Node bằng VXLAN/Geneve hoặc BGP, và thực thi Network Policy thay thế `iptables` bằng **eBPF** ngay trong Linux Kernel. |
| **Programmable Data Plane** | **Ngôn ngữ P4 (Programming Protocol-independent Packet Processors)** | Cho phép kỹ sư lập trình lại cả cách chip ASIC phân tích (Parse) và xử lý các giao thức mới mà không cần chờ hãng sản xuất ra mắt phần cứng mới. |

## 6. So sánh Mạng Truyền thống và SDN

| Tiêu chí | Mạng Truyền thống | Mạng Định nghĩa bằng Phần mềm (SDN) |
| :--- | :--- | :--- |
| **Kiến trúc Control & Data Plane** | Gắn chặt (Coupled) bên trong từng thiết bị phần cứng | Tách rời (Decoupled); Control Plane tập trung tại Controller |
| **Tầm nhìn mạng (Network View)** | Cục bộ (Local) — mỗi thiết bị chỉ biết hàng xóm lân cận | Toàn cục (Global) — Controller nắm toàn bộ bản đồ mạng |
| **Phương thức quản trị & Cấu hình** | Thủ công từng thiết bị qua CLI / SSH / SNMP | Tự động hóa tập trung qua giao diện Web hoặc API (REST/gRPC) |
| **Chuyển tiếp gói tin** | Dựa trên bảng MAC (L2) hoặc bảng định tuyến IP (L3) cố định | Dựa trên bảng luồng đa trường (**Flow Table**: kết hợp L2 + L3 + L4) |
| **Khả năng mở rộng ảo hóa** | Giới hạn $4,096$ VLAN; bị nghẽn do STP chặn cổng dự phòng | Hỗ trợ tới $16.7\text{ triệu}$ phân đoạn (VXLAN VNI); tận dụng $100\%$ băng thông qua ECMP |
| **Tính linh hoạt & Đổi mới** | Phụ thuộc hoàn toàn vào vòng đời nâng cấp firmware của hãng | Tách biệt phần mềm và phần cứng; dễ dàng viết ứng dụng mạng tùy biến |
