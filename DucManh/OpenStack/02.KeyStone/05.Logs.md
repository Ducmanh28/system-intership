# CƠ CHẾ GHI LOG (LOGGING) TRONG OPENSTACK KEYSTONE

> **Tổng quan nhanh:** Keystone sử dụng thư viện **`oslo.log`** để quản lý nhật ký hoạt động. Mặc định trên hệ thống cài đặt thủ công (Ubuntu/Apache WSGI), log ứng dụng được ghi tại `/var/log/keystone/keystone.log` và log HTTP truy cập được ghi tại `/var/log/apache2/keystone*.log`. Đối với nhu cầu tùy biến sâu, Keystone hỗ trợ cấu hình qua tệp `/etc/keystone/logging.conf` bằng tham số `log_config_append`.

## 1. Hai phương thức cấu hình Logging trong Keystone

### Phương thức 1: Cấu hình trực tiếp qua `/etc/keystone/keystone.conf` (Mặc định)
Trong môi trường tiêu chuẩn, thư viện `oslo.log` đọc trực tiếp các tham số dưới mục `[DEFAULT]` của tệp `/etc/keystone/keystone.conf`:

```ini
[DEFAULT]
log_dir = /var/log/keystone
debug = false
use_syslog = false
insecure_debug = false
```

| Tùy chọn (`[DEFAULT]`) | Mô tả kỹ thuật | Lưu ý vận hành |
| :--- | :--- | :--- |
| `log_dir` | Thư mục chứa tệp log mặc định (`keystone.log`). | Thư mục `/var/log/keystone/` phải thuộc sở hữu của user `keystone`. |
| `debug = true` | Bật mức log chi tiết (`DEBUG`) cho toàn bộ dịch vụ. | **Không dùng `--debug` CLI** cho dịch vụ chính vì Keystone chạy dưới Apache WSGI, không phải tiến trình độc lập. |
| `insecure_debug = true` | Ghi ra log cả những thông tin nhạy cảm (lý do xác thực thất bại chi tiết, một số dữ liệu token/payload). | **Chỉ dùng tạm thời khi gỡ lỗi**, tuyệt đối tắt trên môi trường Production. |
| `use_syslog = true` | Đẩy toàn bộ log sang dịch vụ Syslog của hệ điều hành (`/var/log/syslog` hoặc rsyslog tập trung). | Hữu ích khi cần gom log về SIEM/ELK mà không đọc qua tệp cục bộ. |

### Phương thức 2: Cấu hình nâng cao qua `/etc/keystone/logging.conf`
Khi cần tách riêng định dạng log, xoay vòng tệp (log rotation) hoặc điều chỉnh mức độ log riêng cho từng module Python bên trong Keystone, bạn sử dụng tệp cấu hình theo chuẩn **`logging.config` của Python**.

* **Tệp cấu hình:** `/etc/keystone/logging.conf` (có thể tham khảo tệp mẫu `etc/logging.conf.sample` trong mã nguồn Keystone).
* **Cách kích hoạt:** Khai báo trong mục `[DEFAULT]` của `/etc/keystone/keystone.conf`, sau đó khởi động lại Apache2 (`systemctl restart apache2`):

```ini
[DEFAULT]
log_config_append = /etc/keystone/logging.conf
```

> **Lưu ý quan trọng:** Khi tham số `log_config_append` được kích hoạt, toàn bộ quyền điều khiển logging sẽ chuyển hoàn toàn sang tệp `logging.conf`. Các tùy chọn như `log_dir`, `log_file`, `debug` trong `keystone.conf` sẽ **bị vô hiệu hóa**.


## 2. Ba kiểu Formatter (Định dạng dòng log)

**Formatter** quyết định cấu trúc và các trường thông tin xuất hiện trên mỗi dòng log trong tệp nhật ký.

### Bảng so sánh nhanh

| Formatter | Thông tin hiển thị | Trường hợp sử dụng |
| :--- | :--- | :--- |
| `minimal` | Chỉ nội dung thông báo (`message`) | Môi trường cần log cực gọn hoặc đã có hệ thống bên ngoài gắn timestamp. |
| `normal` | Tên logger + Thời gian + Mức độ + Thông báo | Môi trường **Production** tiêu chuẩn (kết hợp mức `INFO` hoặc `WARNING`). |
| `debug` | `normal` + Tên tệp Python + Tên hàm thực thi | Môi trường **Lab / Troubleshoot sâu** (kết hợp mức `DEBUG`). |

### 2.1. `formatter_minimal`
```ini
format=%(message)s
```
* Chỉ ghi nội dung thông báo thuần túy, lược bỏ toàn bộ mốc thời gian, mức độ nghiêm trọng và tên module.

### 2.2. `formatter_normal`
```ini
format=(%(name)s): %(asctime)s %(levelname)s %(message)s
```

| Trường biến | Ý nghĩa | Ví dụ thực tế |
| :--- | :--- | :--- |
| `%(name)s` | Tên logger phát sinh sự kiện | `keystone`, `keystone.auth.controllers` |
| `%(asctime)s` | Thời điểm xảy ra sự kiện | `2026-11-25 14:30:45,123` |
| `%(levelname)s` | Mức độ nghiêm trọng của log | `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `%(message)s` | Nội dung chi tiết thông báo | `Token validated successfully` |

### 2.3. `formatter_debug`
```ini
format=(%(name)s): %(asctime)s %(levelname)s %(module)s %(funcName)s %(message)s
```
Bổ sung thêm 2 trường định vị mã nguồn so với `normal`:

| Trường biến | Ý nghĩa | Ví dụ thực tế |
| :--- | :--- | :--- |
| `%(module)s` | Tên tệp mã nguồn Python (`.py`) | `controllers.py`, `core.py` |
| `%(funcName)s` | Tên hàm (function/method) đang chạy | `authenticate_for_token`, `validate_token` |

> **Khuyến nghị:** Khi chuyển `level=DEBUG` trong `logging.conf`, hãy đổi đồng thời sang `formatter=debug` để xác định chính xác tệp và hàm đang xử lý yêu cầu.


## 3. Cấu trúc chuẩn của tệp `/etc/keystone/logging.conf`

Một tệp `logging.conf` hợp lệ cho trình phân tích `fileConfig()` của Python **bắt buộc** phải khai báo đầy đủ 4 nhóm phần tử (nếu thiếu section khai báo trong `keys=...`, dịch vụ Keystone sẽ báo lỗi không thể khởi động):

```text
[loggers]      → Danh sách các logger được kích hoạt (bắt buộc có 'root')
[handlers]     → Danh sách các đích xuất log (file, console, syslog...)
[formatters]   → Danh sách các định dạng dòng log
[logger_root]  → Cấu hình mức log và handler mặc định cho toàn bộ Keystone
```

### Ví dụ cấu hình `/etc/keystone/logging.conf` hoàn chỉnh

```ini
[loggers]
keys=root

[handlers]
keys=console, file

[formatters]
keys=minimal, normal, debug

[logger_root]
level=INFO
handlers=file

[handler_console]
class=StreamHandler
level=INFO
formatter=normal
args=(sys.stdout,)

[handler_file]
class=handlers.WatchedFileHandler
level=INFO
formatter=normal
args=('/var/log/keystone/keystone.log', 'a')

[formatter_minimal]
format=%(message)s

[formatter_normal]
format=(%(name)s): %(asctime)s %(levelname)s %(message)s

[formatter_debug]
format=(%(name)s): %(asctime)s %(levelname)s %(module)s %(funcName)s %(message)s
```

* **`WatchedFileHandler`:** Tự động phát hiện nếu tệp `/var/log/keystone/keystone.log` bị công cụ `logrotate` đổi tên hoặc nén lại, từ đó tự mở tệp mới mà không cần khởi động lại Apache2.

## 4. Vị trí xem Log theo từng mô hình triển khai OpenStack

Tùy thuộc vào cách bạn cài đặt OpenStack, nhật ký của Keystone sẽ nằm ở các vị trí khác nhau:

| Mô hình triển khai | Vị trí lưu Log / Lệnh kiểm tra | Ghi chú |
| :--- | :--- | :--- |
| **Cài đặt thủ công (Ubuntu + Apache WSGI)** | `/var/log/keystone/keystone.log`<br>`/var/log/apache2/keystone.log`<br>`/var/log/apache2/keystone_access.log` | `keystone.log` chứa log logic ứng dụng; log của Apache chứa mã HTTP (`200`, `401`, `403`, `500`) và lỗi khởi động WSGI. |
| **DevStack** | `journalctl -u devstack@keystone -f` | Các dịch vụ chạy dưới `systemd`, log đẩy trực tiếp vào `journald`. |
| **Kolla-Ansible (Container)** | `/var/log/kolla/keystone/keystone.log`<br>`/var/log/kolla/keystone/keystone-apache-public-access.log` | Được ánh xạ (bind-mount) từ bên trong container ra thư mục log trên host. |
