# CẤU HÌNH CHUYÊN SÂU OPENSTACK KEYSTONE (`keystone.conf`)

> **Tệp cấu hình chính:** `/etc/keystone/keystone.conf`  
> **Định dạng:** INI — phân tách theo `[section]`, mỗi dòng là một cặp `key = value`  
> **Công cụ sinh tệp mẫu chuẩn:** `oslo-config-generator --namespace keystone --output-file /etc/keystone/keystone.conf.sample`  
> **Tài liệu gốc:** [OpenStack Keystone Configuration Options](https://docs.openstack.org/keystone/latest/configuration/config-options.html)

Trong các bản triển khai thực tế (cài đặt thủ công, Kolla-Ansible hoặc DevStack), tệp `/etc/keystone/keystone.conf` chỉ cần khai báo những tham số được tùy biến hoặc ghi đè so với giá trị mặc định. Toàn bộ các tham số không xuất hiện trong tệp sẽ tự động lấy giá trị mặc định được định nghĩa sẵn trong mã nguồn (`oslo.config`).

## 1. Cấu trúc tệp INI và Quy tắc Vận hành

```ini
[section]
key = value
```

### Các kiểu dữ liệu hỗ trợ trong `oslo.config`

| Kiểu dữ liệu | Ví dụ | Ghi chú kỹ thuật |
| :--- | :--- | :--- |
| `boolean` | `true` / `false` | Không phân biệt chữ hoa/thường (`True`, `true`, `1`). |
| `integer` | `64`, `3600` | Số nguyên dùng cho cổng, thời hạn, giới hạn kích thước. |
| `float` | `0.25` | Số thực dấu phẩy động. |
| `string` | `fernet`, `'chuoi co khoang trang'` | Dùng dấu nháy đơn/kép nếu giá trị chứa khoảng trắng hoặc ký tự đặc biệt. |
| `list` | `password,token,application_credential` | Danh sách phân cách bằng dấu phẩy (`,`). |
| `multi-valued` | Khai báo nhiều dòng cùng một `key` | Thường dùng cho `backend_argument` ở `[cache]` hoặc `[oslo_messaging]`. |

### Tham chiếu biến (Variable Substitution)

```ini
[DEFAULT]
rabbit_host = controller
transport_url = rabbit://openstack:secret@$rabbit_host:5672/

# Dùng $$ để thoát ký tự $ nguyên bản trong mật khẩu
[ldap]
password = $$xkj432
```

### Lưu ý vận hành & Áp dụng cấu hình

* Keystone tự động đọc `/etc/keystone/keystone.conf` (có thể chỉ định tệp khác qua cờ `--config-file /path/to/file`).
* Công cụ **`crudini`** được khuyến nghị để thêm/sửa tham số an toàn qua CLI:
  ```bash
  crudini --set /etc/keystone/keystone.conf token expiration 3600
  ```
* **Khởi động lại dịch vụ sau khi sửa cấu hình:**
  ```bash
  # Trên Ubuntu/Debian (Apache2 mod_wsgi - phổ biến nhất)
  systemctl restart apache2

  # Trên RHEL/Rocky/AlmaLinux
  systemctl restart httpd
  ```

## 2. Cấu hình Tối thiểu để Vận hành (Minimal Working Config)

Đây là bộ tham số tối thiểu bắt buộc phải có trước khi đồng bộ cơ sở dữ liệu và khởi chạy Keystone:

```ini
[DEFAULT]
log_dir = /var/log/keystone

[database]
connection = mysql+pymysql://keystone:KEYSTONE_DBPASS@controller/keystone

[token]
provider = fernet

[cache]
enabled = true
backend = dogpile.cache.memcached
backend_argument = url:127.0.0.1:11211

[fernet_tokens]
key_repository = /etc/keystone/fernet-keys
max_active_keys = 3
```

**Trình tự 4 lệnh khởi tạo bắt buộc đi kèm:**

```bash
su -s /bin/sh -c "keystone-manage db_sync" keystone
keystone-manage fernet_setup --keystone-user keystone --keystone-group keystone
keystone-manage credential_setup --keystone-user keystone --keystone-group keystone
keystone-manage bootstrap \
  --bootstrap-password ADMIN_PASS \
  --bootstrap-admin-url http://controller:5000/v3/ \
  --bootstrap-internal-url http://controller:5000/v3/ \
  --bootstrap-public-url http://controller:5000/v3/ \
  --bootstrap-region-id RegionOne
```
## 3. Section `[DEFAULT]` – Thiết lập Chung

```ini
[DEFAULT]
debug = false
insecure_debug = false
log_dir = /var/log/keystone
list_limit = 500
strict_password_check = true
```

| Tham số | Mặc định | Khuyến nghị Prod | Mô tả kỹ thuật |
| :--- | :--- | :--- | :--- |
| `debug` | `False` | `False` | Bật ghi log mức `DEBUG`. Tắt trên Production để tránh phình log và lộ thông tin nội bộ. |
| `insecure_debug` | `False` | `False` | Trả về chi tiết lý do lỗi trong HTTP response gửi về client. **Tuyệt đối tắt trên Production.** |
| `admin_token` | `None` | **Không dùng** | Đã bị loại bỏ (deprecated). Luôn dùng `keystone-manage bootstrap` để khởi tạo quản trị viên. |
| `public_endpoint` | `None` | Để trống | URL gốc trả về trong tài liệu API; chỉ khai báo khi chạy sau Reverse Proxy/Load Balancer phức tạp. |
| `list_limit` | `None` | `500` | Giới hạn số bản ghi tối đa trả về cho các API `LIST`, ngăn chặn nghẽn bộ nhớ khi dữ liệu lớn. |
| `max_project_tree_depth` | `5` | `5` | Độ sâu tối đa của cây Project phân cấp lồng nhau. |
| `max_db_limit` | `1000` | `1000` | Giới hạn cứng số bản ghi tối đa một truy vấn SQL được phép trả về. |
| `max_token_size` | `255` | `255` (`512` nếu dùng JWS) | Kích thước tối đa của chuỗi Token (bytes). Fernet chỉ tốn ~180–250 bytes; JWS cần tăng lên `512`. |
| `strict_password_check` | `False` | `True` | `True` = từ chối mật khẩu vượt quá `max_password_length`; `False` = âm thầm cắt bớt phần thừa. |
| `notification_format` | `cadf` | `cadf` | Chuẩn định dạng sự kiện kiểm toán (Cloud Auditing Data Federation). |

## 4. Section `[database]` – Kết nối Cơ sở dữ liệu

```ini
[database]
connection = mysql+pymysql://keystone:KEYSTONE_DBPASS@controller/keystone
max_pool_size = 10
max_overflow = 20
pool_timeout = 30
pool_recycle = 3600
```

| Tham số | Mặc định | Mô tả kỹ thuật |
| :--- | :--- | :--- |
| `connection` | **Bắt buộc** | Chuỗi kết nối SQLAlchemy (`mysql+pymysql://...`, `postgresql+psycopg2://...`). |
| `max_pool_size` | `5` | Số lượng kết nối SQL duy trì thường trực trong mỗi tiến trình worker. |
| `max_overflow` | `10` | Số kết nối tạm thời được phép mở thêm vượt ngưỡng `max_pool_size` khi cao tải. |
| `pool_timeout` | `30` | Thời gian chờ (giây) để lấy kết nối rảnh từ pool trước khi báo lỗi timeout. |
| `pool_recycle` | `3600` | Tự động làm mới kết nối sau N giây (phải nhỏ hơn `wait_timeout` của MariaDB/MySQL). |


## 5. Section `[token]` – Cấu hình Token

```ini
[token]
provider = fernet
expiration = 3600
allow_expired_window = 172800
caching = true
```

| Tham số | Mặc định | Mô tả kỹ thuật |
| :--- | :--- | :--- |
| `provider` | `fernet` | Cơ chế tạo Token: `fernet` (mã hóa đối xứng, mặc định) hoặc `jws` (chữ ký bất đối xứng ES256). |
| `expiration` | `3600` | Thời gian sống của Token tính bằng giây (`3600` = 1 giờ). |
| `allow_expired_window` | `172800` | Cửa sổ thời gian (48 giờ) cho phép dùng Token đã hết hạn để thực hiện thao tác gia hạn/thu hồi hoặc tác vụ nền dài hạn. |
| `caching` | `True` | Bật bộ nhớ đệm kết quả xác thực Token trên Memcached/Redis. |
| `cache_time` | `None` | Thời gian lưu cache (giây); mặc định kế thừa từ `[cache] expiration_time`. |

## 6. Section `[fernet_tokens]` & `[jws]` – Quản lý Khóa Mật mã

### 6.1. Section `[fernet_tokens]` (Mặc định)

```ini
[fernet_tokens]
key_repository = /etc/keystone/fernet-keys
max_active_keys = 3
```

| Tham số | Mặc định | Mô tả kỹ thuật |
| :--- | :--- | :--- |
| `key_repository` | `/etc/keystone/fernet-keys` | Thư mục lưu trữ khóa đối xứng (phải thuộc quyền `keystone:keystone`, mode `0700`). |
| `max_active_keys` | `3` | Tổng số tệp khóa tối đa được giữ lại đồng thời trong thư mục. |

#### Vòng đời và Quy tắc đánh số khóa Fernet

```text
[Staged Key: 0] ──(rotate)──▶ [Primary Key: N] ──(rotate)──▶ [Secondary Keys: N-1, N-2...] ──▶ [Xóa]
```

* **Staged Key (luôn mang tên `0`):** Khóa dự bị đã được tạo sẵn, chưa dùng để mã hóa nhưng đã sẵn sàng để giải mã.
* **Primary Key (tệp có số thứ tự lớn nhất `N`):** Khóa duy nhất dùng để mã hóa/ký mọi Token mới phát hành.
* **Secondary Keys (các tệp `N-1`, `N-2`...):** Các khóa cũ được hạ cấp, chỉ dùng để giải mã những Token phát hành trước lần xoay vòng mà chưa hết hạn.

```bash
# Khởi tạo kho khóa lần đầu (tạo khóa 0 và khóa 1)
keystone-manage fernet_setup --keystone-user keystone --keystone-group keystone

# Xoay vòng khóa định kỳ (thăng cấp khóa 0 thành N+1, tạo khóa 0 mới và dọn khóa cũ)
keystone-manage fernet_rotate --keystone-user keystone --keystone-group keystone
```

> **Lưu ý Multi-Node:** Công thức chuẩn để tính số khóa cần giữ lại là $\text{max\_active\_keys} = \left(\frac{\text{token\_expiration}}{\text{rotation\_frequency}}\right) + 2$. Toàn bộ các node Keystone trong cụm bắt buộc phải được đồng bộ thư mục `/etc/keystone/fernet-keys/` ngay sau mỗi lần chạy `fernet_rotate`.

### 6.2. Section `[jws]` (Tùy chọn khi dùng `provider = jws`)

```ini
[jws]
key_repository = /etc/keystone/jws-keys
```

* Thư mục này chứa hai thư mục con `private/` (chứa khóa bí mật ký Token tại chỗ) và `public/` (chứa các khóa công khai được phân phối sang toàn bộ cụm để xác thực chữ ký `ES256`).

## 7. Section `[credential]` – Mã hóa Credential

Keystone lưu trữ bí mật của **Application Credentials** và **EC2 Credentials** trong SQL database. Section này cấu hình bộ khóa mã hóa riêng biệt cho các bí mật đó:

```ini
[credential]
driver = sql
provider = fernet
key_repository = /etc/keystone/credential-keys
```

```bash
# Khởi tạo khóa mã hóa credential
keystone-manage credential_setup --keystone-user keystone --keystone-group keystone

# Xoay vòng khóa credential (tự động giải mã và mã hóa lại dữ liệu trong DB sang khóa mới)
keystone-manage credential_rotate --keystone-user keystone --keystone-group keystone
```

## 8. Section `[auth]` – Các Phương thức Xác thực

```ini
[auth]
methods = external,password,token,oauth1,mapped,application_credential,totp
```

| Giá trị trong `methods` | Chức năng |
| :--- | :--- |
| `password` | Xác thực truyền thống bằng Username/User ID và Password. |
| `token` | Dùng Token hiện có để gia hạn hoặc đổi sang phạm vi (Scope) khác. |
| `application_credential` | Xác thực cho script/automation bằng ID & Secret không gắn trực tiếp mật khẩu người dùng. |
| `totp` | Xác thực đa yếu tố (MFA) bằng mã OTP 6 số theo thời gian (cần cấu hình thêm `[totp]`). |
| `mapped` | Liên kết định danh (Federation) qua SAML 2.0 hoặc OpenID Connect (OIDC). |
| `external` | Ủy thác xác thực cho Web Server phía trước (ví dụ Kerberos/X.509 qua biến `REMOTE_USER`). |

## 9. Section `[cache]` – Bộ nhớ đệm Toàn cục

```ini
[cache]
enabled = true
backend = dogpile.cache.memcached
backend_argument = url:controller:11211
expiration_time = 600

[token]
caching = true

[role]
caching = true

[resource]
caching = true

[catalog]
caching = true
```

* **Tại sao Cache mang tính sống còn?** Bản thân Fernet Token không cần truy vấn DB để giải mã, nhưng Keystone vẫn phải đối chiếu thông tin **Role Assignments**, **Project/Domain** và **Service Catalog** trong DB. Bật Memcached giúp giảm tới >90% tải truy vấn SQL khi các dịch vụ Nova, Neutron, Cinder liên tục gọi xác thực Token.

## 10. Section `[catalog]`, `[identity]`, `[assignment]`, `[resource]` & `[oslo_policy]`

```ini
[catalog]
driver = sql
caching = true

[identity]
driver = sql
default_domain_id = default
domain_specific_drivers_enabled = false
domain_config_dir = /etc/keystone/domains
max_password_length = 4096

[assignment]
driver = sql
prohibited_implied_role = admin

[resource]
driver = sql
domain_name_url_safe = strict
project_name_url_safe = strict

[application_credential]
driver = sql
user_limit = -1

[oslo_policy]
policy_file = policy.yaml
enforce_scope = true
enforce_new_defaults = true
```

| Section | Tham số | Ý nghĩa bảo mật & vận hành |
| :--- | :--- | :--- |
| `[assignment]` | `prohibited_implied_role = admin` | Ngăn chặn việc gán ngầm định quyền `admin` thông qua cơ chế Implied Roles, tránh rủi ro leo thang đặc quyền. |
| `[resource]` | `*_name_url_safe = strict` | Chặn các ký tự đặc biệt gây lỗi URL khi truyền tên Domain/Project qua API. |
| `[oslo_policy]` | `enforce_scope = true` | Bắt buộc kiểm tra phạm vi Token (`system`, `domain`, `project`) khớp với quy tắc trong `policy.yaml`. |
| `[oslo_policy]` | `enforce_new_defaults = true` | Kích hoạt chuẩn phân quyền **Secure RBAC** hiện đại. |

## 11. Section `[security_compliance]` – Tuân thủ Chính sách Mật khẩu (PCI-DSS)

> **Lưu ý:** Các quy tắc dưới đây chỉ áp dụng cho người dùng lưu trên **SQL Backend** (không áp dụng cho người dùng xác thực qua LDAP/AD).

```ini
[security_compliance]
lockout_failure_attempts = 6
lockout_duration = 1800
password_expires_days = 90
change_password_upon_first_use = true
unique_last_password_count = 5
minimum_password_age = 1
disable_user_account_days_inactive = 90
password_regex = ^(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}$
password_regex_description = Mat khau phai dai toi thieu 8 ky tu, gom chu hoa, chu thuong va chu so.
```

## 12. Tích hợp LDAP / Active Directory và Domain-Specific Config

Keystone hỗ trợ cấu hình **đa nguồn định danh theo từng Domain** (ví dụ: Domain `default` dùng SQL cho các tài khoản dịch vụ hệ thống, còn Domain `corp` kết nối tới Active Directory/OpenLDAP của doanh nghiệp).

### Bước 1: Bật hỗ trợ cấu hình riêng cho từng Domain trong `/etc/keystone/keystone.conf`

```ini
[identity]
driver = sql
domain_specific_drivers_enabled = true
domain_config_dir = /etc/keystone/domains
```

### Bước 2: Tạo tệp cấu hình riêng `/etc/keystone/domains/keystone.corp.conf`

```ini
[identity]
driver = ldap

[ldap]
url = ldaps://ldap.corp.local:636
user = cn=svc_openstack,ou=ServiceAccounts,dc=corp,dc=local
password = SecretLdapPassword
suffix = dc=corp,dc=local
query_scope = sub

# Ánh xạ User (chỉ đọc)
user_tree_dn = ou=Users,dc=corp,dc=local
user_objectclass = inetOrgPerson
user_id_attribute = uid
user_name_attribute = uid
user_mail_attribute = mail

# Ánh xạ Group (chỉ đọc)
group_tree_dn = ou=Groups,dc=corp,dc=local
group_objectclass = groupOfNames
group_id_attribute = cn
group_name_attribute = cn
group_member_attribute = member

# Bảo mật TLS và Connection Pooling
use_tls = false
tls_cacertfile = /etc/ssl/certs/ca-certificates.crt
tls_req_cert = demand
use_pool = true
pool_size = 10
use_auth_pool = true
auth_pool_size = 50
```

* **Đồng bộ ánh xạ ID (Identity Mapping):**
  ```bash
  keystone-manage mapping_populate --domain-name corp
  ```

## 13. Cấu hình phía Dịch vụ Tích hợp (`keystonemiddleware`)

Để các dịch vụ khác (Nova, Neutron, Glance, Cinder...) xác thực Token với Keystone hiệu quả, cấu hình mục **`[keystone_authtoken]`** trong tệp cấu hình của từng dịch vụ (ví dụ `/etc/nova/nova.conf`):

```ini
[keystone_authtoken]
www_authenticate_uri = http://controller:5000
auth_url = http://controller:5000
memcached_servers = controller:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = nova
password = SERVICE_PASS
token_cache_time = 300
include_service_catalog = false
```

* Đặt `include_service_catalog = false` giúp giảm đáng kể kích thước dữ liệu truyền qua header nội bộ giữa middleware và dịch vụ.

## 14. Bảng Đối chiếu Cấu hình: Lab / Dev vs. Production

| Tham số / Mục cấu hình | Môi trường Lab / Dev | Môi trường Production |
| :--- | :--- | :--- |
| `[DEFAULT] debug` / `insecure_debug` | `true` (khi cần gỡ lỗi) | **`false`** (bắt buộc) |
| `[database] connection` | MariaDB/MySQL cục bộ | Galera Cluster / PostgreSQL HA + Pool |
| `[token] provider` | `fernet` | `fernet` (hoặc `jws` nếu tích hợp JWT) |
| `[token] expiration` | `3600` – `86400` | `3600` (1 giờ) |
| `[cache] backend` | `dogpile.cache.memcached` | Memcached Cluster / Redis Sentinel |
| `[fernet_tokens] max_active_keys` | `3` | `5` – `7` (kèm Cronjob rotate & rsync) |
| `[oslo_policy] enforce_scope` | `true` | **`true`** |
| `[security_compliance]` | Tùy chọn | Bật đầy đủ chuẩn mật khẩu & khóa tài khoản |
| `[DEFAULT] strict_password_check` | `false` | **`true`** |
| Giao thức kết nối API | HTTP (`5000`) | **HTTPS / TLS** qua HAProxy / Nginx |
