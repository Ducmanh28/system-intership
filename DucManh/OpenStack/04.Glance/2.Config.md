# Cấu hình hệ thống OpenStack Glance (`/etc/glance/`)

## 1. Tổng quan thư mục cấu hình `/etc/glance/`

Toàn bộ cấu hình vận hành của dịch vụ **Glance** nằm trong thư mục `/etc/glance/`. Trên các phiên bản OpenStack hiện đại (từ Stein/Train trở đi và đặc biệt trên Ubuntu 24.04), kiến trúc cấu hình đã được tinh gọn đáng kể sau khi loại bỏ hoàn toàn `glance-registry`.

### Danh sách các tệp cấu hình quan trọng

| Tệp cấu hình | Vị trí mặc định | Trạng thái & Vai trò chính |
| :--- | :--- | :--- |
| **`glance-api.conf`** | `/etc/glance/glance-api.conf` | **Tệp cấu hình trung tâm (bắt buộc):** Điều khiển kết nối Database, xác thực Keystone, cấu hình Storage Backend (`[glance_store]`), cổng lắng nghe (`9292`), concurrency lock và logging. |
| **`glance-api-paste.ini`** | `/etc/glance/glance-api-paste.ini` | Định nghĩa **WSGI middleware pipeline** (luồng đi của một HTTP request qua các lớp xác thực token, context, router trước khi vào ứng dụng Glance). |
| **`glance-cache.conf`** | `/etc/glance/glance-cache.conf` | Cấu hình tính năng **Image Cache** cục bộ (dung lượng tối đa, thời gian sống của file tạm, thư mục cache) để tăng tốc độ tải lại các image được truy cập thường xuyên. |
| **`glance-scrubber.conf`** | `/etc/glance/glance-scrubber.conf` | Cấu hình tiến trình dọn dẹp ngầm (**Delayed Delete**). Khi bật xóa trì hoãn, image bị xóa sẽ chuyển sang `pending_delete` và chờ `glance-scrubber` xóa file vật lý sau một khoảng thời gian cấu hình sẵn. |
| **`policy.yaml`** | `/etc/glance/policy.yaml` | Phân quyền chi tiết theo vai trò (**RBAC**): quy định ai được tạo `public` image, ai được xóa/cập nhật metadata, ai chỉ có quyền xem. *(Nếu không tồn tại file tùy chỉnh, Glance dùng policy mặc định trong mã nguồn).* |
| **`glance-registry.conf`** | `/etc/glance/glance-registry.conf` | **Đã bị loại bỏ (Deprecated & Removed):** Chỉ tồn tại ở các bản OpenStack cũ trước Queens/Stein. Không sử dụng trên hệ thống hiện tại. |

### Quyền sở hữu & bảo mật tệp cấu hình
Vì `/etc/glance/glance-api.conf` chứa mật khẩu kết nối MariaDB và thông tin xác thực tài khoản dịch vụ trên Keystone, cần thiết lập quyền chặt chẽ:
* **Owner / Group:** `root:glance`
* **Permission:** `0640` (chỉ `root` được ghi, nhóm `glance` được đọc, người dùng khác không thể xem mật khẩu).

```bash
chown -R root:glance /etc/glance/
chmod 0640 /etc/glance/glance-api.conf
```

## 2. Cơ chế nạp & ghi đè cấu hình (`--config-file` & `--config-dir`)

Glance sử dụng thư viện **`oslo.config`** của OpenStack để phân tích tham số khởi động. Ngoài việc đọc một tệp đơn lẻ, bạn có thể tách cấu hình thành nhiều mảnh nhỏ (modular) trong một thư mục con (ví dụ `/etc/glance/glance-api.d/`).

### Cú pháp khởi chạy tùy chỉnh
```bash
glance-api --config-file=/etc/glance/glance-api.conf --config-dir=/etc/glance/glance-api.d
```

* **`--config-file`:** Chỉ định tệp cấu hình gốc cần nạp đầu tiên.
* **`--config-dir`:** Chỉ định thư mục chứa các tệp cấu hình bổ sung. Glance sẽ quét toàn bộ các tệp có phần mở rộng **`.conf`** bên trong thư mục này theo **thứ tự bảng chữ cái (alphabetical order)**.
* **Quy tắc ghi đè (Override):** Nếu cùng một tham số (ví dụ `debug = True`) xuất hiện ở nhiều tệp, giá trị ở **tệp được đọc sau cùng** sẽ ghi đè và có hiệu lực. Điều này rất hữu ích khi triển khai tự động (Ansible/Puppet) hoặc tách riêng cấu hình tuning/debug mà không sửa trực tiếp file gốc.

## 3. Phân tích chi tiết các section trong `/etc/glance/glance-api.conf`

### 3.1. `[DEFAULT]` — Cấu hình chung, mạng & Logging
Quy định hành vi cơ bản của tiến trình `glance-api`:

```ini
[DEFAULT]
bind_host = 0.0.0.0
bind_port = 9292
log_dir = /var/log/glance
debug = False
workers = 2
```

* `bind_host` / `bind_port`: Địa chỉ IP và cổng dịch vụ lắng nghe (mặc định `9292`).
* `log_dir`: Thư mục ghi log của dịch vụ (`/var/log/glance/glance-api.log`).
* `debug`: Mặc định `False`; chỉ bật `True` tạm thời khi cần theo dõi chi tiết request/SQL/headers lúc gỡ lỗi.
* `workers`: Số tiến trình worker xử lý request song song (mặc định thường bằng số vCPU của node).

### 3.2. `[database]` — Kết nối cơ sở dữ liệu Metadata
Khai báo chuỗi kết nối tới database `glance` trên MariaDB để lưu toàn bộ metadata của image:

```ini
[database]
connection = mysql+pymysql://glance:28072003@172.16.66.60/glance
```

* **`mysql+pymysql`:** Driver Python kết nối tới MariaDB/MySQL.
* **`glance:28072003`:** Username và mật khẩu database của Glance.
* **`172.16.66.60/glance`:** Địa chỉ IP node `controller` và tên database `glance`.

### 3.3. `[keystone_authtoken]` — Xác thực Token qua Keystone
Cho phép middleware của Glance xác thực token người dùng/dịch vụ gửi kèm trong mỗi API request và cache token bằng Memcached:

```ini
[keystone_authtoken]
www_authenticate_uri = http://172.16.66.60:5000
auth_url = http://172.16.66.60:5000
memcached_servers = 172.16.66.60:11211
auth_type = password
project_domain_name = Default
user_domain_name = Default
project_name = service
username = glance
password = 28072003
```

* **`www_authenticate_uri` / `auth_url`:** Endpoint xác thực của Keystone trên `controller` (cổng `5000`).
* **`memcached_servers`:** Máy chủ Memcached (`11211`) dùng để lưu cache token, giảm tải truy vấn lặp lại về Keystone.
* **`project_name = service`, `username = glance`:** Tài khoản dịch vụ đã tạo trên Keystone và được gán role `admin` trong project `service`.

### 3.4. `[paste_deploy]` — Khai báo Pipeline WSGI
Chỉ định pipeline xử lý request từ tệp `glance-api-paste.ini` (bắt buộc trỏ đúng `flavor = keystone` để kích hoạt bộ lọc xác thực Keystone):

```ini
[paste_deploy]
flavor = keystone
```

### 3.5. `[oslo_concurrency]` — Quản lý khóa đồng thời (File Locking)
Tránh xung đột khi nhiều tiến trình `glance-api` cùng đọc/ghi hoặc convert tệp tạm trên hệ thống tệp cục bộ:

```ini
[oslo_concurrency]
lock_path = /var/lib/glance/tmp
```

### 3.6. `[glance_store]` — Cấu hình Storage Backend lưu ảnh đĩa
Đây là phần quyết định **dữ liệu nhị phân của image được lưu ở đâu**. Glance hỗ trợ nhiều backend như `file` (Local Filesystem), `rbd` (Ceph), `swift`, `s3`, `cinder`, `http`.

#### Cấu hình một thư mục lưu trữ cục bộ (chuẩn cho Lab All-in-One)
```ini
[glance_store]
stores = file,http
default_store = file
filesystem_store_datadir = /var/lib/glance/images/
```

* **`stores`:** Danh sách các driver lưu trữ được kích hoạt (`file` cho lưu trữ cục bộ, `http` để hỗ trợ lấy ảnh từ nguồn HTTP bên ngoài).
* **`default_store`:** Backend mặc định khi người dùng upload image mới (`file`).
* **`filesystem_store_datadir`:** Đường dẫn thư mục lưu trữ file ảnh đĩa (mặc định `/var/lib/glance/images/`).

#### Cấu hình nhiều thư mục lưu trữ kèm mức ưu tiên (`filesystem_store_datadirs`)
Khi máy chủ có nhiều phân vùng/ổ đĩa khác nhau, bạn có thể thay `filesystem_store_datadir` bằng **`filesystem_store_datadirs`** theo cú pháp `PATH:PRIORITY` (số `PRIORITY` càng lớn thì mức ưu tiên lưu trữ càng cao):

```ini
[glance_store]
stores = file,http
default_store = file
filesystem_store_datadirs = /var/glance/store:50
filesystem_store_datadirs = /var/glance/store1:100
filesystem_store_datadirs = /var/glance/store2:200
```

* Trong ví dụ trên, Glance sẽ ưu tiên ghi image mới vào `/var/glance/store2` (priority `200`) trước, sau đó mới tới `store1` (`100`) và `store` (`50`).
* **Lưu ý:** Không cấu hình đồng thời cả `filesystem_store_datadir` và `filesystem_store_datadirs` trong cùng một section vì sẽ gây xung đột.

## 4. Kiểm tra cấu hình & vị trí lưu trữ Image thực tế

### 4.1. Lọc nhanh các tham số đang có hiệu lực trong `glance-api.conf`
Bỏ qua các dòng chú thích (`#`) và dòng trống để kiểm tra nhanh toàn bộ cấu hình thực tế đang chạy:

```bash
grep -Ev "^#|^$" /etc/glance/glance-api.conf
```

Hoặc kiểm tra riêng đường dẫn thư mục lưu trữ image:

```bash
grep -E "^filesystem_store_datadir" /etc/glance/glance-api.conf
```

### 4.2. Đối chiếu file vật lý trên ổ đĩa với Metadata trên OpenStack CLI
Mỗi image khi upload thành công sẽ được lưu trong `/var/lib/glance/images/` dưới dạng một tệp nhị phân có **tên trùng khớp chính xác với `ID` (UUID) của image đó**:

```bash
# 1. Kiểm tra tệp vật lý trong thư mục lưu trữ của Glance
ls -lh /var/lib/glance/images/
# Ví dụ kết quả:
# -rw-r----- 1 glance glance 16M Nov 26 15:30 010ffd94-4d26-4dc6-be5b-1a7a31a3686a

# 2. Đối chiếu với danh sách image quản lý bởi Glance API
source ~/admin-openrc
openstack image list
```

* Nếu thấy một `ID` xuất hiện trong `openstack image list` ở trạng thái `active`, bạn sẽ tìm thấy đúng tệp dữ liệu tương ứng tại `/var/lib/glance/images/<ID>` thuộc quyền sở hữu của user/group `glance:glance`.
