# Các lệnh thường sử dụng với OpenStack Glance

Có 2 bộ công cụ dòng lệnh (CLI) để thao tác với dịch vụ **Glance**:

| CLI | Gói cài đặt (Package) | Trạng thái |
| :--- | :--- | :--- |
| `openstack image ...` | `python-openstackclient` | **Khuyến nghị** — Unified CLI thống nhất cho toàn bộ OpenStack |
| `glance ...` | `python-glanceclient` | **Legacy** — Vẫn hoạt động nhưng đã ngừng phát triển tính năng mới |

> **Lưu ý trước khi chạy lệnh:** Luôn nạp thông tin xác thực Keystone bằng lệnh `source ~/admin-openrc` (hoặc tệp `openrc` của user/project tương ứng).

## 1. OpenStack CLI (`openstack image ...`) — Khuyến nghị

### 1.1. Liệt kê Image (`list`)

```bash
# Liệt kê toàn bộ image có quyền xem
openstack image list
```

Các tùy chọn lọc nâng cao:

```bash
# Lọc theo tên chính xác
openstack image list --name cirros

# Lọc theo trạng thái (active, queued, saving, killed, deactivated...)
openstack image list --status active

# Lọc theo mức độ hiển thị (Visibility)
openstack image list --public
openstack image list --private
openstack image list --shared
openstack image list --community

# Hiển thị đầy đủ thông tin (disk_format, container_format, size, owner, checksum...)
openstack image list --long

# Chỉ hiển thị các cột cần thiết cho gọn bảng
openstack image list -c ID -c Name -c "Disk Format" -c Status -c Visibility
```

### 1.2. Xem chi tiết Image (`show`)

```bash
openstack image show <IMAGE_ID | image_name>
```

Lệnh này trả về toàn bộ thông tin kỹ thuật của image: `id`, `name`, `status`, `visibility`, `disk_format`, `container_format`, `size`, `os_hash_value` (checksum), `properties` và `locations` (nếu admin được phép xem).

### 1.3. Tạo và Upload Image (`create`)

```bash
# 1. Upload file image từ local (cách phổ biến nhất)
openstack image create "Ubuntu-24.04" \
  --file /opt/images/noble-server-cloudimg-amd64.img \
  --disk-format qcow2 \
  --container-format bare \
  --public

# 2. Tạo image và yêu cầu Glance tự tải từ URL (phương thức web-download)
openstack image create "cirros-0.6.2" \
  --container-format bare \
  --disk-format qcow2 \
  --public \
  --import-method web-download \
  --uri http://download.cirros-cloud.net/0.6.2/cirros-0.6.2-x86_64-disk.img

# 3. Tạo image chuẩn cho môi trường thực tế với đầy đủ tham số phần cứng & OS
openstack image create "Ubuntu-24.04-LTS" \
  --file /opt/images/ubuntu-24.04-server.qcow2 \
  --disk-format qcow2 \
  --container-format bare \
  --min-disk 10 \
  --min-ram 1024 \
  --public \
  --property os_distro=ubuntu \
  --property os_version=24.04 \
  --property hw_disk_bus=virtio \
  --property hw_vif_model=virtio \
  --property hw_qemu_guest_agent=yes \
  --tag ubuntu \
  --tag lts
```

Bảng giải thích các tham số tạo Image:

| Tham số | Ý nghĩa | Ví dụ |
| :--- | :--- | :--- |
| `--file` | Đường dẫn tệp image nguồn trên máy cục bộ | `--file /opt/ubuntu.qcow2` |
| `--disk-format` | Định dạng đĩa thực tế của image | `qcow2`, `raw`, `vmdk`, `iso` |
| `--container-format` | Định dạng đóng gói container bên ngoài | `bare` (phổ biến nhất) |
| `--public` | Mọi project đều thấy và sử dụng được (thường yêu cầu quyền admin) | _(cờ boolean)_ |
| `--private` | Chỉ project tạo ra image mới thấy và dùng được | _(cờ boolean)_ |
| `--shared` | Chỉ định thủ công từng project được phép truy cập | _(cờ boolean)_ |
| `--community` | Mọi project đều dùng được nếu biết ID, nhưng không hiện mặc định trong `list` | _(cờ boolean)_ |
| `--min-disk` | Dung lượng ổ đĩa tối thiểu (GB) để boot được image này | `--min-disk 20` |
| `--min-ram` | Dung lượng RAM tối thiểu (MB) để boot được image này | `--min-ram 2048` |
| `--property` | Gắn cặp metadata tùy chỉnh (chỉ dẫn cho Nova/Hypervisor) | `--property hw_disk_bus=virtio` |
| `--tag` | Gắn nhãn tìm kiếm nhanh cho image | `--tag production` |
| `--protected` | Khóa chống xóa nhầm image | _(cờ boolean)_ |

### 1.4. Tải xuống Image (`save`)

```bash
openstack image save --file <output_file> <IMAGE_ID | image_name>
```

Ví dụ:
```bash
openstack image save --file /tmp/cirros-backup.qcow2 cirros-0.6.2
```

### 1.5. Cập nhật thông tin, trạng thái và thuộc tính (`set` / `unset`)

```bash
# Đổi tên image
openstack image set --name "Ubuntu-24.04-LTS-v2" <IMAGE_ID | image_name>

# Thay đổi mức độ hiển thị (visibility)
openstack image set --public <IMAGE_ID | image_name>
openstack image set --private <IMAGE_ID | image_name>
openstack image set --shared <IMAGE_ID | image_name>
openstack image set --community <IMAGE_ID | image_name>

# Bật / tắt khóa chống xóa (protected)
openstack image set --protected <IMAGE_ID | image_name>
openstack image set --unprotected <IMAGE_ID | image_name>

# Tạm vô hiệu hóa (deactivate) hoặc kích hoạt lại (reactivate) image
openstack image deactivate <IMAGE_ID | image_name>
openstack image reactivate <IMAGE_ID | image_name>

# Cập nhật yêu cầu tài nguyên tối thiểu
openstack image set --min-disk 20 --min-ram 2048 <IMAGE_ID | image_name>

# Thêm hoặc cập nhật property
openstack image set --property os_distro=ubuntu --property hw_disk_bus=virtio <IMAGE_ID | image_name>

# Xóa một property
openstack image unset --property os_distro <IMAGE_ID | image_name>

# Thêm hoặc xóa tag
openstack image set --tag production --tag ubuntu <IMAGE_ID | image_name>
openstack image unset --tag ubuntu <IMAGE_ID | image_name>
```

### 1.6. Xóa Image (`delete`)

```bash
# Xóa một image
openstack image delete <IMAGE_ID | image_name>

# Xóa nhiều image cùng lúc
openstack image delete <IMAGE_ID_1> <IMAGE_ID_2>
```

> **Lưu ý:** Nếu image đang bật cờ `protected`, lệnh xóa sẽ báo lỗi `403 Forbidden`. Bạn phải chạy `openstack image set --unprotected <IMAGE_ID>` trước khi xóa.

## 2. Chia sẻ Image giữa các Project (Image Sharing)

Cơ chế `shared` cho phép chủ sở hữu image chia sẻ riêng cho một hoặc nhiều project cụ thể mà không cần công khai (`public`) cho toàn hệ thống.

### 2.1. Tạo image ở chế độ `shared`

```bash
openstack image create "cirros-shared" \
  --file cirros-0.6.2-x86_64-disk.img \
  --disk-format qcow2 \
  --container-format bare \
  --shared
```

### 2.2. Thêm project vào danh sách được chia sẻ (Project sở hữu thực hiện)

```bash
openstack image add project <IMAGE_ID | image_name> <PROJECT_ID | project_name>

# Ví dụ: chia sẻ image "cirros-shared" cho project "demo"
openstack image add project cirros-shared demo
```

### 2.3. Kiểm tra danh sách project (member) của image

```bash
openstack image member list <IMAGE_ID | image_name>
```

### 2.4. Phản hồi lời mời chia sẻ (Project nhận thực hiện)

Sau khi được thêm vào, image mặc định ở trạng thái `pending` và chưa tự hiện ra trong `openstack image list` của project nhận cho tới khi được chấp nhận:

```bash
# Chấp nhận image được chia sẻ
openstack image set --accept <IMAGE_ID>

# Từ chối image được chia sẻ
openstack image set --reject <IMAGE_ID>

# Đưa về lại trạng thái chờ (pending)
openstack image set --pending <IMAGE_ID>
```

### 2.5. Thu hồi quyền chia sẻ của một project

```bash
openstack image remove project <IMAGE_ID | image_name> <PROJECT_ID | project_name>
```
## 3. Glance CLI (`glance ...`) — Legacy

> Bộ lệnh `glance` thuộc gói `python-glanceclient` là công cụ cũ (legacy), chỉ nên dùng khi bảo trì script cũ hoặc gỡ lỗi cấp thấp.

```bash
# Liệt kê image
glance image-list

# Tạo và upload image trong 1 bước kèm thanh tiến trình
glance image-create \
  --name cirros-test \
  --disk-format qcow2 \
  --container-format bare \
  --visibility public \
  --file cirros-0.6.2-x86_64-disk.img \
  --progress

# Tạo image 2 bước (tạo bản ghi rỗng -> upload file sau)
glance image-create --name cirros-upload --container-format bare --disk-format qcow2
glance image-upload --file cirros-0.6.2-x86_64-disk.img --progress <IMAGE_ID>

# Xem chi tiết, vô hiệu hóa, kích hoạt lại và xóa
glance image-show <IMAGE_ID>
glance image-deactivate <IMAGE_ID>
glance image-reactivate <IMAGE_ID>
glance image-delete <IMAGE_ID> [<IMAGE_ID> ...]
```
## 4. Cơ chế Image Import nâng cao (Interoperable Image Import)

Ngoài cách upload luồng dữ liệu trực tiếp (`--file`), Glance hỗ trợ quy trình **Image Import** (gồm các bước `queued` $\rightarrow$ `uploading` $\rightarrow$ `importing` $\rightarrow$ `active`) cho phép tiền xử lý ảnh đĩa (như tự động convert định dạng, kiểm tra chữ ký) hoặc nhập ảnh từ nguồn từ xa.

### 4.1. Kiểm tra các phương thức Import được bật trên Server

```bash
openstack image import-info
```

### 4.2. `glance-direct` (Upload lên vùng đệm `staging` rồi kích hoạt import)

```bash
# Bước 1: Tạo bản ghi image
openstack image create "my-imported-image" \
  --disk-format qcow2 \
  --container-format bare

IMAGE_ID=$(openstack image show "my-imported-image" -f value -c id)

# Bước 2: Đẩy file lên vùng staging của Glance
openstack image stage --file /path/to/image.qcow2 "$IMAGE_ID"

# Bước 3: Kích hoạt tiến trình import
openstack image import --method glance-direct "$IMAGE_ID"
```

### 4.3. `web-download` (Glance tự tải image từ URL)

```bash
openstack image create "CentOS-Stream-9" \
  --disk-format qcow2 \
  --container-format bare \
  --public \
  --import-method web-download \
  --uri "https://cloud.centos.org/centos/9-stream/x86_64/images/CentOS-Stream-GenericCloud-9-latest.x86_64.qcow2"
```

### 4.4. `copy-image` (Sao chép image sang Storage Backend khác)

Áp dụng khi hệ thống cấu hình nhiều backend lưu trữ (`enabled_backends`, ví dụ từ local `file` sang `ceph`):

```bash
openstack image import \
  --import-method copy-image \
  --stores ceph_store \
  <IMAGE_ID>
```

## 5. Quản lý Image Cache

Khi bật tính năng Image Cache (`glance-cache.conf`), Glance lưu bản sao các image hay được tải để giảm tải cho Storage Backend.

```bash
# Xem danh sách các image đang nằm trong cache
openstack image cache list

# Xóa một image cụ thể khỏi cache
openstack image cache delete <IMAGE_ID>

# Xóa toàn bộ dữ liệu cache (sử dụng CLI legacy hoặc dọn bằng glance-cache-manage)
glance cache-clear

# Đưa một image vào hàng đợi tải trước vào cache (prefetch)
openstack image cache queue <IMAGE_ID>
```

## 6. Quản lý Metadef (Metadata Definitions)

**Metadef** cung cấp bộ định nghĩa chuẩn các thuộc tính (`namespace`, `object`, `property`) cho image, flavor, volume... giúp giao diện Horizon và người dùng gắn đúng tên thuộc tính kỹ thuật.

```bash
# Liệt kê toàn bộ namespace hiện có
openstack image metadef namespace list

# Xem chi tiết một namespace (ví dụ cấu hình Libvirt/QEMU)
openstack image metadef namespace show OS::Compute::LibvirtImage

# Tạo namespace tùy chỉnh mới
openstack image metadef namespace create \
  --public \
  --display-name "My Custom Namespace" \
  "org.example.custom"

# Xóa namespace
openstack image metadef namespace delete "org.example.custom"

# Liệt kê và xem object bên trong namespace
openstack image metadef object list <namespace>
openstack image metadef object show <namespace> <object-name>

# Liệt kê resource type và gắn namespace vào resource type của Glance
openstack image metadef resource type list
openstack image metadef namespace resource type create <namespace> --name OS::Glance::Image
```

## 7. Quản trị dịch vụ, Quota & Database (Admin)

### 7.1. Kiểm tra trạng thái dịch vụ & Endpoint trên `controller` (`172.16.66.60`)

```bash
# Kiểm tra tiến trình systemd của glance-api
systemctl status glance-api --no-pager -l

# Kiểm tra cổng lắng nghe mặc định 9292
ss -tlnp | grep 9292

# Kiểm tra healthcheck của Glance API
curl -i http://172.16.66.60:9292/healthcheck

# Kiểm tra phiên bản API Glance phản hồi
curl -s http://172.16.66.60:9292/ | python3 -m json.tool

# Liệt kê các endpoint đã đăng ký trên Keystone
openstack endpoint list --service image
```

> **Ghi chú đối với môi trường DevStack:** Trong DevStack, Glance chạy qua `uwsgi` + Apache reverse proxy (`systemctl status devstack@g-api`) và truy cập qua đường dẫn `http://<IP>/image` thay vì cổng `9292` trực tiếp.

### 7.2. Quản lý Quota (Unified Limits qua Keystone)

Khi Glance cấu hình sử dụng Keystone Unified Limits (`use_keystone_limits = true`), admin quản lý giới hạn lưu trữ image như sau:

```bash
# Xem các giới hạn mặc định đã đăng ký cho service glance
openstack registered limit list --service glance

# Tạo giới hạn riêng cho một project cụ thể (ví dụ tối đa 100 image)
openstack limit create \
  --project <PROJECT_ID> \
  --service glance \
  --resource-limit 100 \
  image_count_total

# Xem danh sách limit đang áp dụng cho project
openstack limit list --project <PROJECT_ID>
```

### 7.3. Quản trị Database Schema (`glance-manage`)

Luôn chạy các lệnh `glance-manage` dưới quyền user `glance` để đảm bảo đúng quyền truy cập tệp cấu hình và log:

```bash
# Đồng bộ schema database (chạy khi cài đặt mới hoặc nâng cấp phiên bản)
su -s /bin/sh -c "glance-manage db_sync" glance

# Kiểm tra phiên bản schema database hiện tại
su -s /bin/sh -c "glance-manage db_version" glance

# Nạp dữ liệu định nghĩa metadata mặc định (metadefs) vào database
su -s /bin/sh -c "glance-manage db_load_metadefs" glance
```

## 8. Quy trình kiểm thử nhanh & các lệnh xử lý hàng loạt

### 8.1. Tải và upload CirrOS để kiểm tra hoạt động của Glance

```bash
# 1. Tải file ảnh CirrOS gọn nhẹ (~16MB)
wget -P /tmp http://download.cirros-cloud.net/0.6.2/cirros-0.6.2-x86_64-disk.img

# 2. Upload lên Glance
openstack image create "cirros-0.6.2" \
  --file /tmp/cirros-0.6.2-x86_64-disk.img \
  --disk-format qcow2 \
  --container-format bare \
  --public

# 3. Kiểm tra metadata và đối chiếu file vật lý trên store
openstack image list
ls -lh /var/lib/glance/images/
```

### 8.2. Script kiểm tra toàn bộ vòng đời Image (Create $\rightarrow$ Show $\rightarrow$ Download $\rightarrow$ Delete)

```bash
#!/bin/bash
set -e

IMG_FILE="/tmp/cirros-0.6.2-x86_64-disk.img"
IMG_NAME="test-image-$(date +%s)"

echo "=== 1. Tạo và upload image test ==="
IMAGE_ID=$(openstack image create \
  --file "$IMG_FILE" \
  --disk-format qcow2 \
  --container-format bare \
  --private \
  "$IMG_NAME" \
  -f value -c id)
echo "Image ID: $IMAGE_ID"

echo "=== 2. Kiểm tra trạng thái image ==="
openstack image show "$IMAGE_ID" -f value -c status

echo "=== 3. Tải thử image về local ==="
openstack image save --file /tmp/test-download.img "$IMAGE_ID"
ls -lh /tmp/test-download.img

echo "=== 4. Dọn dẹp image và file tạm ==="
openstack image delete "$IMAGE_ID"
rm -f /tmp/test-download.img

echo "=== Hoàn thành kiểm thử Glance ==="
```

### 8.3. Các lệnh xử lý nhanh thường dùng

```bash
# Lấy nhanh UUID của image theo tên
openstack image show "Ubuntu-24.04" -f value -c id

# Liệt kê danh sách image dạng bảng rút gọn
openstack image list -f table -c ID -c Name -c Status -c Size

# Đếm tổng số image hiện có
openstack image list -f value -c ID | wc -l

# Xóa toàn bộ các image đang ở trạng thái lỗi (killed)
for id in $(openstack image list --status killed -f value -c ID); do
    openstack image delete "$id"
done

# Xuất toàn bộ ID các image đang active ra tệp
openstack image list --status active -f value -c ID > /tmp/active-image-ids.txt

# Bật bảo vệ chống xóa (protected) cho toàn bộ image public
for id in $(openstack image list --public -f value -c ID); do
    openstack image set --protected "$id"
done
```

## 9. Bảng tra cứu nhanh (Quick Reference)

| Tác vụ | Lệnh chuẩn (`openstack` CLI) |
| :--- | :--- |
| Liệt kê tất cả image | `openstack image list` |
| Lọc image theo trạng thái | `openstack image list --status active` |
| Xem chi tiết image | `openstack image show <name/id>` |
| Upload image mới | `openstack image create "name" --file img.qcow2 --disk-format qcow2 --container-format bare --public` |
| Tải image về máy | `openstack image save --file out.qcow2 <name/id>` |
| Đổi tên image | `openstack image set --name "new-name" <name/id>` |
| Đổi quyền hiển thị | `openstack image set --public \| --private \| --shared <name/id>` |
| Vô hiệu hóa image | `openstack image deactivate <name/id>` |
| Kích hoạt lại image | `openstack image reactivate <name/id>` |
| Khóa chống xóa | `openstack image set --protected <name/id>` |
| Gỡ khóa chống xóa | `openstack image set --unprotected <name/id>` |
| Xóa image | `openstack image delete <name/id>` |
| Xóa một property | `openstack image unset --property <key> <name/id>` |
| Chia sẻ image cho project | `openstack image add project <image> <project>` |
| Xem danh sách project được chia sẻ | `openstack image member list <name/id>` |
