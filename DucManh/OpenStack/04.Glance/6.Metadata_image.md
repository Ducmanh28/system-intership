# Tìm hiểu về Metadata Image trong OpenStack Glance

## 1. Metadata của Glance Image là gì?

### 1.1. Định nghĩa

**Metadata của Glance image** là tập hợp các **thuộc tính mô tả** (cặp `key-value` và các trường cốt lõi) đi kèm với mỗi image, được lưu trong **database** (MariaDB/MySQL) của Glance, tách biệt hoàn toàn với tệp dữ liệu nhị phân thực tế trên Storage Backend.

> **Ví dụ:** Nếu tệp `.qcow2` là "quyển sách", thì metadata là "bìa sách + mục lục + phiếu mượn" — không phải nội dung bên trong, nhưng cho biết đó là sách gì, cần bao nhiêu tài nguyên để đọc và ai được phép đọc.

### 1.2. Tại sao Metadata quan trọng?

| Vai trò | Giải thích kỹ thuật |
| :--- | :--- |
| **Mô tả image** | Tên, định dạng đĩa, dung lượng, hệ điều hành — giúp người dùng và Horizon nhận diện chính xác image. |
| **Kiểm soát tài nguyên** | `min_disk`, `min_ram` — Nova từ chối khởi tạo VM nếu flavor có dung lượng đĩa hoặc RAM nhỏ hơn mức tối thiểu. |
| **Hướng dẫn Hypervisor** | Nhóm thuộc tính `hw_*` chỉ dẫn cho Nova/libvirt/QEMU cấu hình đúng driver phần cứng ảo (`virtio`, `q35`, `uefi`...). |
| **Toàn vẹn & Bảo mật** | `os_hash_value`, chữ ký số `img_signature_*`, `os_secure_boot` — đảm bảo image không bị sửa đổi trái phép. |
| **Phân quyền & Chia sẻ** | `visibility`, `owner`, `protected` — kiểm soát phạm vi truy cập và chống xóa nhầm. |
| **Tự động hóa lúc Boot** | `img_config_drive`, `os_admin_user` — phối hợp với `cloud-init` để cấu hình hệ điều hành bên trong VM. |
| **Lập lịch Nova Scheduler** | `ImagePropertiesFilter` và `trait:*` giúp Nova chọn đúng Compute node có kiến trúc/phần cứng tương thích. |

### 1.3. Cây phân loại Metadata

```text
Metadata của Glance Image
├── Core Properties          — Glance tự quản lý (id, name, status, size, visibility...)
├── Hardware Properties      — Nova/libvirt đọc để cấu hình phần cứng VM (hw_disk_bus, hw_vif_model...)
├── OS Properties            — Mô tả hệ điều hành & hành vi OS (os_distro, os_version, os_type...)
├── Security Properties      — Chữ ký số, Secure Boot, mã hóa RAM (img_signature*, os_secure_boot...)
├── Architecture Properties  — Kiến trúc CPU, loại hypervisor (architecture, hypervisor_type, vm_mode)
├── Resource Traits          — Yêu cầu tính năng phần cứng host cho Scheduler (trait:HW_CPU_X86_AVX2...)
└── Custom Properties        — Thuộc tính mở rộng do người dùng/admin tự định nghĩa (key=value tùy ý)
```

### 1.4. Quy ước tiền tố (Prefix)

| Prefix | Nhóm thuộc tính | Thành phần đọc & xử lý |
| :--- | :--- | :--- |
| *(không prefix)* | Core & Architecture | Glance, Nova API, Nova Scheduler, người dùng |
| `hw_` | Hardware | Nova Compute, libvirt, QEMU/KVM |
| `os_` | Operating System | Horizon Dashboard, Nova, `cloud-init` |
| `img_` | Image-level flags & Security | Nova, Glance, Barbican |
| `vmware_` | VMware-specific | VMware vCenter driver |
| `trait:` | Placement Resource Traits | Nova Scheduler (`Placement`) |
| *(tùy ý)* | Custom Properties | Người dùng, admin, hệ thống tự động hóa nội bộ |

> **Lưu ý:** Tiền tố **`os_glance`** được **Glance giữ riêng** cho metadata nội bộ. Người dùng và admin **không được phép** tạo hoặc sửa bất kỳ thuộc tính nào bắt đầu bằng `os_glance` (API sẽ từ chối với lỗi `403 Forbidden`).

## 2. Các thuộc tính cốt lõi (Core Properties)

Đây là các trường dữ liệu chuẩn trong schema của Glance, phần lớn do hệ thống tự quản lý hoặc kiểm soát chặt chẽ kiểu dữ liệu.

### 2.1. Thuộc tính định danh

| Thuộc tính | Kiểu dữ liệu | Mô tả | Ví dụ |
| :--- | :--- | :--- | :--- |
| `id` | UUID | Mã định danh duy nhất của image (Glance tự sinh hoặc chỉ định lúc tạo) | `010ffd94-4d26-4dc6-be5b-1a7a31a3686a` |
| `name` | string | Tên hiển thị của image (không bắt buộc duy nhất) | `Ubuntu-24.04-LTS` |
| `owner` | UUID | Project ID sở hữu image | `5b4c1d2155004acf849cd3aac03b8f36` |

### 2.2. Thuộc tính định dạng

| Thuộc tính | Giá trị hợp lệ | Mô tả |
| :--- | :--- | :--- |
| `disk_format` | `raw`, `qcow2`, `vmdk`, `vhd`, `vhdx`, `vdi`, `iso`, `ploop` | Định dạng tệp ảnh đĩa thực tế |
| `container_format` | `bare`, `ovf`, `ova`, `aki`, `ari`, `ami`, `docker`, `compressed` | Định dạng vỏ bọc container bên ngoài |

> **Thực tế triển khai:** Với KVM/QEMU trên OpenStack, hầu hết image sử dụng `disk_format=qcow2` (hoặc `raw` nếu dùng Ceph RBD) và `container_format=bare`.

### 2.3. Thuộc tính trạng thái và vòng đời

| Thuộc tính | Giá trị | Mô tả |
| :--- | :--- | :--- |
| `status` | `queued`, `saving`, `uploading`, `importing`, `active`, `deactivated`, `killed`, `pending_delete`, `deleted` | Trạng thái hiện tại của image |
| `created_at` | ISO 8601 datetime | Thời điểm khởi tạo bản ghi image |
| `updated_at` | ISO 8601 datetime | Thời điểm cập nhật metadata/trạng thái gần nhất |

**Sơ đồ vòng đời trạng thái:**

```text
queued ──► saving / importing ──► active
                                    │
                  ┌─────────────────┼─────────────────┐
                  ▼                 ▼                 ▼
               killed          deactivated     pending_delete ──► deleted
```

### 2.4. Thuộc tính kích thước và toàn vẹn dữ liệu

| Thuộc tính | Kiểu dữ liệu | Mô tả |
| :--- | :--- | :--- |
| `size` | integer (bytes) | Kích thước tệp nhị phân thực tế lưu trên store |
| `virtual_size` | integer (bytes) | Kích thước đĩa ảo khi bung ra (ví dụ file `qcow2` nặng 600 MB nhưng `virtual_size` là 10 GB) |
| `checksum` | string | Mã băm MD5 (legacy, giữ lại để tương thích ngược) |
| `os_hash_algo` | string | Thuật toán băm chuẩn mới (mặc định `sha512`) |
| `os_hash_value` | string | Giá trị băm tính theo `os_hash_algo` |

> **Khuyến nghị:** Luôn đối chiếu `os_hash_value` + `os_hash_algo` (`sha512`) thay vì `checksum` (MD5) để xác minh tính toàn vẹn dữ liệu.

### 2.5. Thuộc tính phân quyền và chia sẻ

| Thuộc tính | Giá trị | Mô tả |
| :--- | :--- | :--- |
| `visibility` | `public`, `private`, `shared`, `community` | Phạm vi hiển thị và quyền sử dụng image |
| `protected` | `true` / `false` | Khi `true`, chặn mọi thao tác xóa image cho tới khi gỡ cờ |
| `member_status` | `accepted`, `rejected`, `pending` | Trạng thái chấp nhận chia sẻ từ phía project được mời (`shared`) |

**So sánh chi tiết các mức `visibility`:**

| Visibility | Ai nhìn thấy mặc định trong `image list`? | Ai được phép dùng để tạo VM? |
| :--- | :--- | :--- |
| `public` | Mọi project | Mọi project (mặc định chỉ admin mới tạo được) |
| `community` | Không hiện mặc định (phải lọc `--community` hoặc biết ID) | Mọi project (không cần bước `accept`) |
| `shared` | Project sở hữu + project đã `accepted` | Project sở hữu + project được mời và đã `accepted` |
| `private` | Chỉ project sở hữu (`owner`) | Chỉ project sở hữu (`owner`) |

### 2.6. Thuộc tính giới hạn tài nguyên tối thiểu

| Thuộc tính | Đơn vị | Mô tả |
| :--- | :--- | :--- |
| `min_disk` | GB | Dung lượng ổ đĩa gốc tối thiểu; Nova từ chối nếu flavor disk nhỏ hơn |
| `min_ram` | MB | Dung lượng RAM tối thiểu; Nova từ chối nếu flavor RAM nhỏ hơn |

```bash
# Ví dụ: Windows Server cần tối thiểu 40 GB disk và 2048 MB RAM
openstack image set \
  --min-disk 40 \
  --min-ram 2048 \
  "Windows-Server-2022"
```

### 2.7. Tags

`tags` là danh sách các nhãn chuỗi tự do (không có giá trị đi kèm) giúp phân loại và tìm kiếm nhanh image:

```bash
# Gắn nhiều tag cho image
openstack image set --tag ubuntu --tag lts --tag production <IMAGE_ID>

# Lọc image theo tag
openstack image list --tag ubuntu
```

## 3. Các thuộc tính phần cứng (Hardware Properties — `hw_*`)

Nhóm `hw_*` được **Nova Compute** đọc và chuyển thành cấu hình phần cứng ảo trong tệp định nghĩa XML của **libvirt/QEMU/KVM**.

### 3.1. CPU & Topology

| Thuộc tính | Kiểu | Giá trị hợp lệ | Mô tả |
| :--- | :--- | :--- | :--- |
| `hw_cpu_sockets` | int | $\ge 1$ | Số socket CPU ảo cấp cho VM |
| `hw_cpu_cores` | int | $\ge 1$ | Số core trên mỗi socket |
| `hw_cpu_threads` | int | $\ge 1$ | Số luồng (thread) trên mỗi core |
| `hw_cpu_policy` | str | `shared` (mặc định), `dedicated` | `dedicated` gắn cố định (pinning) vCPU vào pCPU vật lý |
| `hw_cpu_thread_policy` | str | `prefer` (mặc định), `isolate`, `require` | Chính sách phân bổ luồng SMT/Hyper-Threading khi dùng `dedicated` |
| `hw_pmu` | bool | `true` / `false` | Bật/tắt vPMU (tắt để giảm độ trễ cho workload realtime) |

**Chi tiết `hw_cpu_thread_policy`:**

| Giá trị | Hành vi lập lịch |
| :--- | :--- |
| `prefer` | Ưu tiên đặt các vCPU lên cùng sibling thread vật lý nếu host có SMT, nhưng không bắt buộc |
| `isolate` | Bắt buộc mỗi vCPU nằm trên một core vật lý độc lập (không chia sẻ sibling thread) |
| `require` | Bắt buộc host phải có SMT/Hyper-Threading; từ chối nếu host không hỗ trợ |

```bash
# Ví dụ cấu hình CPU pinning cô lập luồng cho workload hiệu năng cao
openstack image set \
  --property hw_cpu_policy=dedicated \
  --property hw_cpu_thread_policy=isolate \
  "HPC-Image"
```

### 3.2. Bộ nhớ (Memory & NUMA)

| Thuộc tính | Kiểu | Giá trị | Mô tả |
| :--- | :--- | :--- | :--- |
| `hw_mem_page_size` | str | `small`, `large`, `any` | Kích thước trang nhớ (`large` kích hoạt HugePages để giảm TLB miss) |
| `hw_numa_nodes` | int | $\ge 1$ | Số lượng NUMA node ảo cấu hình cho VM |
| `hw_mem_encryption` | bool | `true` / `false` | Bật mã hóa bộ nhớ RAM phần cứng (AMD SEV) |
| `hw_mem_encryption_model` | str | `amd-sev`, `amd-sev-es` | Chọn mô hình mã hóa RAM cụ thể |

### 3.3. Đĩa & Lưu trữ (Disk & Storage)

| Thuộc tính | Giá trị hợp lệ | Mô tả |
| :--- | :--- | :--- |
| `hw_disk_bus` | `virtio`, `scsi`, `ide`, `sata`, `usb`, `xen`, `uml`, `lxc` | Chuẩn giao tiếp ổ đĩa ảo |
| `hw_scsi_model` | `virtio-scsi`, `lsilogic` | Bộ điều khiển SCSI ảo (dùng kèm khi `hw_disk_bus=scsi`) |
| `hw_cdrom_bus` | `ide`, `scsi`, `sata` | Chuẩn giao tiếp ổ CD/DVD ảo |
| `hw_serial_port_count` | int | Số cổng serial ảo gắn vào VM |
| `hw_rescue_bus` | `scsi`, `virtio`, `ide`, `usb` | Chuẩn bus dùng khi khởi động vào chế độ rescue |
| `hw_rescue_device` | `cdrom`, `disk`, `floppy` | Loại thiết bị gắn khi khởi động chế độ rescue |

> **Thực hành tốt nhất (Best Practice):** Với Linux trên KVM, luôn đặt `hw_disk_bus=virtio` (hoặc `hw_disk_bus=scsi` kèm `hw_scsi_model=virtio-scsi` nếu cần hỗ trợ TRIM/discard) để đạt hiệu năng I/O cao nhất.

### 3.4. Card mạng (Network)

| Thuộc tính | Giá trị hợp lệ | Mô tả |
| :--- | :--- | :--- |
| `hw_vif_model` | `virtio`, `e1000`, `e1000e`, `rtl8139`, `ne2k_pci`, `pcnet`, `vmxnet3`, `igb` | Loại card mạng ảo (NIC) |
| `hw_vif_multiqueue_enabled` | `true` / `false` | Bật đa hàng đợi `virtio-net` giúp tận dụng nhiều vCPU xử lý gói tin |
| `hw_virtio_packed_ring` | `true` / `false` | Bật cơ chế Packed Virtqueue (tối ưu thông lượng gói tin nhỏ) |

**Gợi ý chọn `hw_vif_model`:**
* **`virtio`:** Lựa chọn tối ưu cho mọi hệ điều hành Linux trên KVM.
* **`e1000` / `e1000e`:** Dùng cho Windows hoặc hệ điều hành cũ chưa tích hợp sẵn driver VirtIO.
* **`vmxnet3`:** Dành cho hạ tầng chạy VMware vSphere.

### 3.5. Đồ họa & Hiển thị (Video & Display)

| Thuộc tính | Giá trị hợp lệ | Mô tả |
| :--- | :--- | :--- |
| `hw_video_model` | `vga`, `cirrus`, `vmvga`, `xen`, `qxl`, `virtio`, `gop`, `bochs`, `none` | Card đồ họa ảo (`none` tắt hoàn toàn GPU ảo khi dùng GPU Passthrough) |
| `hw_video_ram` | int (MB) | Dung lượng VRAM cấp cho card đồ họa ảo |
| `hw_pointer_model` | `usbtablet` | Thiết bị trỏ tọa độ tuyệt đối giúp con trỏ chuột trên VNC/SPICE console không bị lệch |

### 3.6. Khởi động & Firmware (Boot & Chipset)

| Thuộc tính | Giá trị | Mô tả |
| :--- | :--- | :--- |
| `hw_firmware_type` | `bios` (mặc định), `uefi` | Chế độ firmware khởi động (`uefi` bắt buộc cho Secure Boot và Windows 11) |
| `hw_firmware_stateless` | `true` / `false` | Khởi động UEFI không lưu biến NVRAM qua các lần reboot |
| `hw_machine_type` | `pc`, `q35` (KVM); `hyperv-gen1`, `hyperv-gen2` (Hyper-V) | Loại chipset bo mạch ảo (`q35` hỗ trợ PCIe hiện đại) |
| `hw_boot_menu` | `true` / `false` | Hiển thị menu chọn thiết bị boot lúc khởi động |


## 4. Các thuộc tính hệ điều hành (OS Properties — `os_*`)

Nhóm `os_*` cung cấp ngữ cảnh về hệ điều hành bên trong image cho Horizon, Nova và `cloud-init`.

### 4.1. Nhận diện hệ điều hành

| Thuộc tính | Giá trị ví dụ | Mô tả |
| :--- | :--- | :--- |
| `os_distro` | `ubuntu`, `debian`, `rocky`, `rhel`, `centos`, `fedora`, `windows` | Tên bản phân phối viết thường theo chuẩn `libosinfo` |
| `os_version` | `24.04`, `22.04`, `9`, `2022` | Phiên bản phát hành của hệ điều hành |
| `os_type` | `linux`, `windows` | Loại nhân hệ điều hành (ảnh hưởng cách Nova xử lý thiết bị/mật khẩu) |
| `os_admin_user` | `ubuntu`, `debian`, `cloud-user`, `Administrator` | Tài khoản quản trị mặc định của cloud image |
| `os_command_line` | string | Tham số dòng lệnh nhân Linux (kernel boot args) |

### 4.2. Hành vi vận hành & Config Drive

| Thuộc tính | Giá trị | Mô tả |
| :--- | :--- | :--- |
| `os_require_quiesce` | `yes` / `no` | Yêu cầu đóng băng hệ thống tệp (quiesce) trước khi tạo snapshot (cần QEMU Guest Agent) |
| `os_shutdown_timeout` | int (giây) | Thời gian chờ tắt máy mềm (graceful shutdown) trước khi rút nguồn ảo (mặc định `60`) |
| `img_config_drive` | `mandatory`, `optional` (mặc định) | Bắt buộc đính kèm ổ đĩa ISO `config-drive` chứa metadata khi mạng không có DHCP/Metadata service |


## 5. Thuộc tính bảo mật & xác thực (Security Properties)

### 5.1. Ký số xác thực Image (Image Signing với Barbican)

Glance phối hợp với dịch vụ quản lý khóa **Barbican** để xác minh chữ ký số của image trước khi Nova tải về chạy:

| Thuộc tính | Mô tả |
| :--- | :--- |
| `img_signature` | Chuỗi chữ ký số của tệp image (mã hóa Base64) |
| `img_signature_hash_method` | Thuật toán băm dùng để ký (`SHA-256`, `SHA-3-256`...) |
| `img_signature_key_type` | Loại khóa bất đối xứng (`RSA-PSS`, `DSA`, `ECC-SECT571K1`, `ECC-SECT571R1`...) |
| `img_signature_certificate_uuid` | UUID của chứng thư số (Certificate) lưu trên Barbican |

```text
Upload Image ──► Glance lưu img_signature + certificate_uuid
                      │
                      ▼
Nova tạo VM  ──► Tải image + lấy certificate từ Barbican ──► Verify chữ ký ──► Khởi tạo VM
```

### 5.2. Secure Boot, Ẩn Hypervisor & Mã hóa RAM

| Thuộc tính | Giá trị | Mô tả |
| :--- | :--- | :--- |
| `os_secure_boot` | `required`, `optional`, `disabled` (mặc định) | Yêu cầu UEFI Secure Boot (khi đặt `required`, bắt buộc `hw_firmware_type=uefi`) |
| `img_hide_hypervisor_id` | `true` / `false` | Ẩn cờ nhận diện máy ảo (CPUID hypervisor bit), thường dùng khi chạy GPU passthrough với driver NVIDIA |
| `hw_mem_encryption` | `true` / `false` | Kích hoạt mã hóa RAM phần cứng (AMD SEV) |

```bash
# Ví dụ cấu hình cho Windows 11 yêu cầu UEFI + Secure Boot
openstack image set \
  --property hw_firmware_type=uefi \
  --property os_secure_boot=required \
  --property hw_machine_type=q35 \
  "Windows-11"
```

## 6. Thuộc tính kiến trúc & ảo hóa

Được **Nova Scheduler (`ImagePropertiesFilter`)** sử dụng để lọc ra các Compute node có năng lực ảo hóa phù hợp:

| Thuộc tính | Giá trị phổ biến | Mô tả |
| :--- | :--- | :--- |
| `architecture` | `x86_64`, `aarch64`, `ppc64le`, `s390x`, `i686` | Kiến trúc tập lệnh CPU mà image hỗ trợ |
| `hypervisor_type` | `qemu`, `kvm`, `xen`, `hyperv`, `vmware`, `ironic` | Loại hypervisor tương thích (`qemu` áp dụng cho cả QEMU và KVM) |
| `vm_mode` | `hvm`, `xen`, `uml`, `exe` | Chế độ ảo hóa (`hvm` = ảo hóa phần cứng toàn phần) |
| `img_type` | `whole-disk`, `partition` | Phân loại đĩa cho **Ironic** (Bare Metal) |
| `vmware_adaptertype` | `lsiLogic`, `lsiLogicsas`, `busLogic`, `ide`, `paraVirtual` | Chuẩn bộ điều khiển lưu trữ cho VMware |
| `vmware_ostype` | string (ví dụ `ubuntu64Guest`) | Định danh hệ điều hành khách theo chuẩn VMware GuestID |


## 7. Thuộc tính Resource Traits (`trait:*`)

**Resource Traits** kết nối trực tiếp yêu cầu của image với hệ thống **Placement**, ép Nova Scheduler chỉ chọn những Compute node có gắn trait tương ứng.

* **Cú pháp duy nhất hợp lệ:** `trait:<TÊN_TRAIT>=required`
* **Phạm vi áp dụng:** Có hiệu lực với cả VM boot từ image lẫn VM boot từ volume được tạo từ image đó.

| Ví dụ Trait | Ý nghĩa lập lịch |
| :--- | :--- |
| `trait:HW_CPU_X86_AVX2=required` | Bắt buộc Compute node có tập lệnh CPU AVX2 |
| `trait:HW_CPU_X86_AVX512F=required` | Bắt buộc Compute node hỗ trợ AVX-512 |
| `trait:STORAGE_DISK_SSD=required` | Bắt buộc Compute node sử dụng ổ cứng SSD |
| `trait:HW_GPU_API_VULKAN=required` | Bắt buộc Compute node có GPU hỗ trợ Vulkan |

```bash
openstack image set \
  --property "trait:HW_CPU_X86_AVX2=required" \
  --property "trait:STORAGE_DISK_SSD=required" \
  "ML-Training-Image"
```

## 8. Thuộc tính tùy chỉnh (Custom Properties) & Bảo vệ thuộc tính

### 8.1. Quản lý Custom Properties

Người dùng và quản trị viên có thể tự định nghĩa mọi cặp `key=value` phục vụ quản trị nội bộ (nhóm vận hành, môi trường, mã chi phí...):

```bash
# Gán custom properties
openstack image set \
  --property environment=production \
  --property team=devops \
  --property cost_center=CC-001 \
  <IMAGE_ID>

# Tìm kiếm image theo custom property
openstack image list --property team=devops

# Xóa bớt custom property
openstack image unset --property cost_center <IMAGE_ID>
```

### 8.2. Bảo vệ thuộc tính (`property-protections.conf`)

Quản trị viên có thể kiểm soát quyền tạo, đọc, sửa, xóa từng nhóm thuộc tính bằng tệp `/etc/glance/property-protections.conf` (khai báo qua `property_protection_file` trong `glance-api.conf`):

```ini
# Chỉ role admin mới được đặt/sửa/xóa os_secure_boot; mọi user đã xác thực (@) được đọc
[os_secure_boot]
create = admin
read = @
update = admin
delete = admin

# Nhóm hw_* chỉ admin được chỉnh sửa
[hw_.*]
create = admin
read = @
update = admin
delete = admin

# Các custom property còn lại cho phép mọi user đã xác thực thao tác
[.*]
create = @
read = @
update = @
delete = @
```

## 9. Metadata Definitions (Metadef)

**Metadef** là danh mục chuẩn hóa schema metadata (gồm `Namespace`, `Object`, `Property`, `Tag`) giúp Horizon hiển thị giao diện chọn thuộc tính trực quan và đảm bảo đặt tên thống nhất trên toàn hệ thống.

* **Schema vs Giá trị thực:** Metadef chỉ định nghĩa khuôn mẫu (`schema`). Khi người dùng gán thuộc tính lên image, giá trị thực được lưu trong bảng `image_properties` của Glance DB.
* **Khác biệt tiền tố giữa Image và Flavor:** Cùng một tính năng phần cứng nhưng tên khóa khác nhau giữa hai dịch vụ:
  * Trên Glance Image: `hw_cpu_policy=dedicated` (dùng dấu gạch dưới `_`)
  * Trên Nova Flavor: `hw:cpu_policy=dedicated` (dùng dấu hai chấm `:`)

```bash
# Nạp bộ định nghĩa Metadef mặc định của OpenStack vào database (chạy dưới user glance)
su -s /bin/sh -c "glance-manage db_load_metadefs" glance

# Liệt kê và xem chi tiết các namespace
openstack image metadef namespace list
openstack image metadef namespace show OS::Compute::LibvirtImage
```
## 10. Phối hợp giữa Glance Metadata, Nova và Cloud-init

Glance Metadata và `cloud-init` **bổ sung cho nhau** ở hai giai đoạn khác nhau của vòng đời máy ảo:

| Tiêu chí | Glance Metadata | Cloud-init |
| :--- | :--- | :--- |
| **Nơi lưu trữ** | Database của dịch vụ Glance | Gói/cấu hình bên trong tệp image + nguồn Metadata/ConfigDrive |
| **Thành phần đọc** | Nova Scheduler, Nova Compute, libvirt | Tiến trình `cloud-init` bên trong Guest OS |
| **Thời điểm tác động** | **Trước & trong lúc** dựng phần cứng ảo (XML) | **Sau khi** nhân hệ điều hành VM khởi động |
| **Phạm vi điều khiển** | Phần cứng ảo (disk bus, NIC, CPU, RAM, UEFI) & chọn host | Cấu hình trong OS (hostname, SSH key, user, network IP, script) |
| **Khả năng thay đổi** | Sửa động bất cứ lúc nào bằng `openstack image set` | Đóng gói sẵn trong image hoặc truyền qua `user-data` lúc tạo VM |

### Luồng xử lý từ lúc gọi tạo VM đến khi VM sẵn sàng

```text
1. User chạy: openstack server create --image <IMG_ID> --flavor <FLV_ID> ...
       │
       ▼
2. Nova Scheduler:
   ├── Đọc min_disk, min_ram -> đối chiếu với Flavor
   ├── Đọc architecture, hypervisor_type, vm_mode (ImagePropertiesFilter)
   └── Đọc trait:* -> truy vấn Placement chọn Compute node đạt chuẩn
       │
       ▼
3. Nova Compute (trên Compute node được chọn):
   ├── Tải image từ Glance & xác minh os_hash_value / img_signature
   └── Đọc nhóm hw_* (hw_disk_bus, hw_vif_model, hw_firmware_type...) -> sinh tệp libvirt XML
       │
       ▼
4. QEMU / KVM khởi động máy ảo với cấu hình phần cứng ảo tương ứng
       │
       ▼
5. Cloud-init bên trong VM chạy lần đầu:
   └── Nạp SSH key, đặt hostname, cấu hình mạng, chạy user-data -> VM sẵn sàng phục vụ
```

## 12. Giới hạn & Lưu ý vận hành

1. **Giới hạn số lượng thuộc tính:** Tham số `image_property_quota` trong `/etc/glance/glance-api.conf` mặc định giới hạn tối đa **128 properties** trên mỗi image.
2. **Tiền tố bị khóa:** Không bao giờ dùng prefix `os_glance*` cho thuộc tính tùy chỉnh.
3. **Thuộc tính không kế thừa khi Snapshot (`non_inheritable_image_properties`):** Khi chụp snapshot từ một VM đang chạy, một số thuộc tính đặc thù của image gốc (như `img_signature*` hoặc một số cờ khởi tạo ban đầu) sẽ bị Nova loại bỏ để tránh xung đột trên snapshot mới.
4. **Tính tương thích Hypervisor:** Phần lớn thuộc tính `hw_*` chỉ có tác dụng với driver **libvirt (KVM/QEMU)**; `vmware_*` chỉ dành cho VMware; `img_type` chỉ dành cho Ironic.
