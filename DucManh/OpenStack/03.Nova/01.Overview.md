# TỔNG QUAN KIẾN TRÚC OPENSTACK NOVA (COMPUTE)

**OpenStack Nova** là dịch vụ **Compute** cốt lõi của OpenStack, chịu trách nhiệm cấp phát, điều phối và quản lý vòng đời máy ảo (VM / Instance) trên toàn bộ cụm hạ tầng. Nova được thiết kế theo kiến trúc **phân tán, hướng thông điệp bất đồng bộ (Message-Driven)**, tách biệt rõ giữa tầng điều khiển (**Control Plane**) và tầng thực thi ảo hóa (**Compute / Hypervisor Plane**).

## 1. Vai trò và Hệ sinh thái Tích hợp của Nova

Nova không hoạt động độc lập mà đóng vai trò trung tâm kết nối các dịch vụ hạ tầng OpenStack khác để khởi tạo nên một máy ảo hoàn chỉnh:

* **Keystone (Identity):** Xác thực Token, kiểm tra phân quyền RBAC (`oslo.policy`) và tra cứu Service Catalog.
* **Placement:** Theo dõi chính xác tồn kho tài nguyên (Resource Providers, Inventories) và mức phân bổ (Allocations) của từng máy chủ vật lý trước khi lập lịch.
* **Glance (Image):** Cung cấp Image hệ điều hành (`QCOW2`, `RAW`, `ISO`...) để khởi tạo ổ đĩa gốc cho Instance hoặc lưu trữ Snapshot.
* **Neutron (Networking):** Cấp phát card mạng ảo (Port), địa chỉ IP, Security Group và kết nối VLAN/VXLAN cho máy ảo.
* **Cinder (Block Storage):** Cung cấp ổ đĩa lưu trữ bền vững (Block Volume) để gắn thêm hoặc khởi động máy ảo trực tiếp từ Volume (Boot from Volume).

## 2. Kiến trúc các Thành phần Cốt lõi

Trên mô hình triển khai chuẩn (hoặc All-in-One trên node `controller` `172.16.66.60`), Nova bao gồm các tiến trình (daemons) chuyên biệt sau:

| Thành phần | Vị trí triển khai | Vai trò & Chức năng kỹ thuật |
| :--- | :--- | :--- |
| **`nova-api`** | Controller Node | Tiếp nhận toàn bộ yêu cầu REST API từ client (qua WSGI/Apache2), xác thực Keystone, kiểm tra Quota/Policy và đẩy tác vụ xuống hàng đợi RPC. |
| **`nova-scheduler`** | Controller Node | Truy vấn **Placement** để lấy danh sách Compute Host đạt chuẩn, sau đó áp dụng bộ lọc (**Filters**) và chấm điểm (**Weighers**) để chọn host tối ưu nhất. |
| **`nova-conductor`** | Controller Node | Đóng vai trò lớp trung gian bảo mật giữa `nova-compute` và Database (ngăn `nova-compute` truy cập trực tiếp SQL DB), đồng thời điều phối các tác vụ phức tạp (build, resize, migration). |
| **`nova-compute`** | Compute Node (hoặc All-in-One) | Chạy trực tiếp trên hypervisor (như **KVM/libvirt**), nhận lệnh qua RPC để sinh cấu hình XML máy ảo, tải Image từ Glance, gắn Port từ Neutron và điều khiển trạng thái nguồn VM. |
| **`nova-metadata`** | Controller / Network Node | Cung cấp dữ liệu cấu hình khởi tạo (Hostname, SSH Public Key, `user-data` cho `cloud-init`) cho máy ảo qua địa chỉ nội bộ `169.254.169.254`. |
| **`nova-novncproxy`** | Controller Node | Cổng proxy WebSocket chuyển tiếp giao thức VNC/SPICE từ giao diện Web (Horizon) hoặc CLI tới màn hình console của máy ảo trên Compute Host. |

## 3. Kiến trúc Cơ sở dữ liệu & Hàng đợi của Nova

Để đảm bảo khả năng mở rộng ngang (Horizontal Scaling) cho các cụm hàng nghìn máy chủ, Nova chia cơ sở dữ liệu thành nhiều thành phần độc lập:

1. **`nova_api` (Database):** Lưu trữ thông tin toàn cục cấp API như ánh xạ Cell (`cell_mappings`), Flavor, Host Aggregates và bảng định tuyến Instance.
2. **`nova_cell0` (Database):** Kho lưu trữ đặc biệt dành cho các Instance bị lỗi ngay từ bước lập lịch (không tìm được Compute Host phù hợp) trước khi kịp gán vào một Cell thực tế.
3. **`nova` / `nova_cell1` (Database):** Lưu trữ trạng thái chi tiết của toàn bộ Instance, Block Device Mapping, PCI devices và lịch sử thao tác (`instance_actions`) thuộc Cell tương ứng.
4. **RabbitMQ (RPC Message Queue):** Kênh giao tiếp bất đồng bộ giúp các tiến trình `nova-api`, `nova-scheduler`, `nova-conductor` và `nova-compute` trao đổi thông điệp mà không khóa lẫn nhau.


## 4. Luồng Cấp phát Máy ảo (Instance Boot Workflow)

Quá trình từ lúc người dùng chạy lệnh `openstack server create` đến khi máy ảo chạy (`ACTIVE`) diễn ra qua 7 bước tuần tự:

```text
[Client / CLI]
      │ 1. POST /v2.1/servers (Image, Flavor, Network, Keypair)
      ▼
  [nova-api] ──────► (Xác thực Keystone & Kiểm tra Quota, tạo bản ghi DB)
      │ 2. RPC call
      ▼
[nova-conductor] ──► 3. Yêu cầu chọn host ──► [nova-scheduler] ◄──► [Placement API]
      │                                              │ (Lọc & Chấm điểm Host)
      │ 4. Nhận Compute Host đích ◄──────────────────┘
      │
      │ 5. RPC cast (build_and_run_instance)
      ▼
[nova-compute]
      ├──► 6a. Gọi Glance API: Tải Image về thư mục cache (_base)
      ├──► 6b. Gọi Neutron API: Tạo Port, gán IP & Security Group
      ├──► 6c. Gọi Cinder API: Gắn Volume (nếu boot từ volume)
      └──► 7. Gọi Libvirt / KVM: Khởi tạo domain VM ──► Cập nhật trạng thái ACTIVE
```

## 5. Các Khái niệm Vận hành Trọng tâm

### 5.1. Flavor (Cấu hình phần cứng ảo)
Định nghĩa tài nguyên cấp phát cho một máy ảo, bao gồm:
* **vCPU:** Số lõi xử lý ảo.
* **RAM (MB):** Dung lượng bộ nhớ chính.
* **Root Disk (GB):** Dung lượng ổ đĩa hệ điều hành chính.
* **Ephemeral Disk / Swap (GB):** Ổ đĩa tạm thời (mất dữ liệu khi xóa VM) và phân vùng swap.
* **Extra Specs:** Các thuộc tính mở rộng (ví dụ giới hạn IOPS ổ đĩa, băng thông mạng, hoặc ghim CPU/NUMA).

### 5.2. Nova Cells (Phân vùng mở rộng)
Cơ chế chia cụm Compute lớn thành các phân vùng độc lập (**Cells**). Mỗi Cell có Database và cụm RabbitMQ riêng, giúp tránh hiện tượng nghẽn cổ chai ở cơ sở dữ liệu trung tâm và cô lập sự cố hạ tầng.

### 5.3. Ba lớp Trạng thái của Instance
Nova theo dõi vòng đời máy ảo thông qua 3 thuộc tính trạng thái tách biệt:
* **`vm_state`:** Trạng thái ổn định ở tầng quản lý (`building`, `active`, `stopped`, `paused`, `suspended`, `resized`, `error`).
* **`task_state`:** Tác vụ tức thời đang diễn ra (`scheduling`, `block_device_mapping`, `networking`, `spawning`, `migrating`, `deleting`). Khi hoàn tất tác vụ, giá trị này trở về `None`.
* **`power_state`:** Trạng thái nguồn thực tế báo cáo từ Hypervisor KVM/libvirt (`Running`, `Shutdown`, `Paused`, `Crashed`).
