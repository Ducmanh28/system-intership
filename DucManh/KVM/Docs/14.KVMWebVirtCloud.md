# Quản lý hạ tầng KVM trên Ubuntu với WebVertCloud
## Khái niệm
Là web-based KVM management tool, mã nguồn mở, viết bằng Django(Python).(WebVirtCloud=Django app)

Nó là một lớp quản lý KVM qua libvirt nhưng hiển thị dưới dạng giao diện web.

Có thể coi như một giải pháp thay thế Virt-Manager GUI, nhưng chạy qua trình duyệt.

## Chức năng chính
Quản lý host: kết nối đến 1 hoặc nhiều kvm host qua SSH

Quản lý VM:
- Tạo, start, stop, restart, delete VM.
- Snapshot, clone, migrate
- Console VNC/SPICE ngay trên web.

Quản lý Storage:
- Upload ISO, qcow2.
- Tạo disk mới, attack/detach disk

Quản lý network:
- Tạo và cấu hình bridge, NAT, isolated network

Multi-user:
- Có quản lý user & role (admin, user)
- Hữu ích khi nhiều người cùng sử dụng KVM

## Kiến trúc tổng thể
Ví dụ trong hệ thống lab gồm 3 thiết bị
```Plaintext
[ Trình duyệt Web ] 
       │
       ├─ (HTTP Port 80) ──> [ Nginx Reverse Proxy ]
       │                           │
       │                           ├─ / ──────────> (HTTP 8000) ─> [ Gunicorn WSGI ] ─> [ Django App ]
       │                           │                                                           │
       │                           │                                                   (SSH / libvirt API)
       │                           │                                                           │
       │                           │                                                           ▼
       │                           └─ /console/ ──> (WS 6080) ───> [ novncd Daemon ] ─> [ Host 1 & Host 2 ]
```
### Thành Phần
**Django Framework**: Chịu trách nhiệm về logic quản lý máy ảo, phân quyền người dùng, dựng cấu hình XML và giao tiếp với KVM qua thư viện libvirt-python.

**Gunicorn (WSGI HTTP Server)**: Chạy ứng dụng Django dưới dạng tiến trình backend lắng nghe ở cổng nội bộ 127.0.0.1:8000.

**novncd (noVNC Daemon)**: Script Python đi kèm WebVirtCloud, làm proxy chuyển đổi giữa giao thức VNC thuần (từ KVM Node) sang WebSocket để truyền hình ảnh màn hình console VM lên trình duyệt.

**Nginx (Reverse Proxy)**: Đứng ở cổng 80, điều hướng truy vấn HTTP thường vào Gunicorn và truy vấn WebSocket vào novncd.

**Supervisor**: Tiến trình quản lý ngầm, đảm bảo Gunicorn và novncd luôn chạy và tự khởi động lại nếu bị crash.

**SSH Key**: Xác thực không mật khẩu giúp WebVirtCloud gửi câu lệnh Libvirt từ NFS Server sang Host 1 (`172.16.66.58`) và Host 2 (`172.16.66.59`).
### Mô tả luồng
Mô hình hoạt động của toàn bộ hệ thống được vận hành dựa trên sự kết hợp chặt chẽ giữa 3 luồng xử lý độc lập: Luồng Quản trị & Điều khiển (Management), Luồng Lưu trữ (Storage), và Luồng Hiển thị (Console Proxy).

#### Luồng Quản trị & Điều khiển (Management Flow)
```Plaintext
[Trình duyệt] ──(HTTP:80)──> [Nginx .60] ──> [Gunicorn:8000] ──> [Django App]
                                                                        │
                                                               (SSH / libvirt)
                                                                        │
                                                                        ▼
                                                          [libvirtd trên .58 / .59]
```
Yêu cầu từ Admin: Khi thao tác trên Web UI (ví dụ: Bật/Tắt VM, tạo VM mới), trình duyệt gửi HTTP Request tới Nginx trên máy quản lý `.60`.

Xử lý ứng dụng: Nginx điều hướng request cho Gunicorn (cổng 8000) để ứng dụng WebVirtCloud (Django) xử lý logic.

Thực thi lệnh KVM: Django App sử dụng SSH Key của user www-data để kết nối SSH không mật khẩu sang Host 1 (`172.16.66.58`) hoặc Host 2 (`172.16.66.59`), gọi trực tiếp API của dịch vụ libvirtd để điều khiển QEMU/KVM bên dưới.

#### Luồng Đọc/Ghi Dữ liệu Đĩa ảo (Storage I/O Flow)
```Plaintext
[Host 1 (.58) / Host 2 (.59)] ◄── NFS Mount (/var/lib/libvirt/images) ──► [NFS Server .60]
  ├── Running VM2 (Linked Clone) ──► Đọc ubuntu-template.qcow2 & Ghi vm2.qcow2
  └── Running VM3 (Full Clone)   ──► Đọc/Ghi trực tiếp vm3.qcow2
```
Kết nối lưu trữ: Host 1 và Host 2 mount chung thư mục /var/lib/libvirt/images từ NFS Server (`.60`).

Hoạt động của Linked Clone (VM2 trên Host 1): Khi VM2 vận hành, KVM trên Host 1 gửi yêu cầu đọc dữ liệu hệ điều hành gốc từ file `ubuntu-template.qcow2` qua mạng NFS, đồng thời ghi dữ liệu thay đổi phát sinh vào `vm2.qcow2`.

Hoạt động của Full Clone (VM3 trên Host 2): KVM trên Host 2 thực hiện đọc/ghi độc lập hoàn toàn trên file `vm3.qcow2` nằm trên NFS.

#### Luồng Hiển thị Màn hình Console (noVNC / WebSocket Flow)
```Plaintext
[Trình duyệt] ──(WebSocket)──> [Nginx .60] ──> [novncd:6080] ──(VNC:5900+)──> [VM trên Host .58/.59]
```
Khởi tạo kết nối: Khi bấm mở thẻ Console trên Web UI, trình duyệt mở một kết nối WebSocket tới Nginx (đường dẫn /console/).

Chuyển tiếp WebSocket: Nginx nhận diện header Upgrade: websocket và chuyển tiếp luồng dữ liệu tới daemon novncd (chạy cổng 6080 trên .60).

Bắt cầu VNC: novncd mở kết nối VNC tới cổng VNC nội bộ (mặc định 5900, 5901...) của máy ảo tương ứng đang chạy ở Host 1 (`.58`) hoặc Host 2 (`.59`).

Hiển thị: `novncd` đóng vai trò phiên dịch dữ liệu giữa giao thức VNC thuần và WebSocket, hiển thị hình ảnh màn hình OS trực tiếp lên giao diện HTML5 của trình duyệt
