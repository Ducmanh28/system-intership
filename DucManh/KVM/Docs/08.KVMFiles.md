# Hệ thống File và Folders trong KVM
Có 2 nơi lưu file chính trong KVM được tóm tắt theo bảng sau

|Đặc điểm|`/etc/libvirt/qemu`|`/var/lib/libivirt/qemu`|
|-|-|-|
|Data|Các file cấu hình|Các file trạng thái|
|Định dạng|XML|Log, Socket, Ram dump, NVRAM|
|Mục đích|Thông tin máy ảo|Thông tin trạng thái máy ảo|
|Delete|Khi xóa máy ảo|Chứa dữ liệu tạm thời khi máy đang chạy|

## Chi tiết từng thư mục và các file bên trong
### Thư mục cấu hình máy ảo (/etc/libvirt/qemu/)
Thư mục này chứa toàn bộ định nghĩa phần cứng ảo hóa dạng văn bản XML.

<vm-name>.xml (ví dụ: vm1.xml): File mô tả toàn bộ cấu hình phần cứng của máy ảo vm1 (RAM, CPU, đĩa đệm, card mạng, thiết bị hiển thị).

Thư mục autostart/: Chứa các đường link mềm (symbolic link) trỏ tới file XML gốc trong /etc/libvirt/qemu/. Khi một VM được bật tính năng tự khởi động cùng Host (virsh autostart vm1), một symlink vm1.xml sẽ tự động được tạo tại đây.

Cảnh báo quan trọng: KHÔNG dùng các trình soạn thảo như nano hay vim để sửa trực tiếp file /etc/libvirt/qemu/vm1.xml khi dịch vụ libvirtd đang chạy. Các thay đổi sẽ bị đè hoặc bị vô hiệu hóa. Phải luôn dùng lệnh virsh edit vm1 để việc biên dịch và kiểm tra cú pháp XML được thực hiện an toàn.

### Thư mục ổ đĩa ảo (/var/lib/libvirt/images/)
Đây là khu vực mặc định (Default Storage Pool) lưu trữ hệ điều hành và dữ liệu của máy ảo.

- `<vm-name>.qcow2` hoặc `<vm-name>.raw`: Chứa toàn bộ OS, dữ liệu, bảng phân vùng đĩa của Guest OS.

- Các file `.iso`: Đĩa quang ảo dùng để boot/cài đặt hệ điều hành.

### Thư mục cấu hình mạng (/etc/libvirt/qemu/networks/)
Chứa file định nghĩa các Virtual Network do Libvirt quản lý.

`default.xml`: Cấu hình mạng NAT mặc định (192.168.122.0/24), quản lý giao diện virbr0.

### Thư mục autostart/: 
Chứa symlink của các network được cấu hình tự bật khi máy Host boot.

### Thư mục Log (`/var/log/libvirt/qemu/`)
Khu vực quan trọng nhất để tra cứu sự cố (troubleshooting) khi máy ảo không thể khởi động hoặc sập đột ngột.

`<vm-name>.log` (ví dụ: `vm1.log`): Ghi lại lệnh khởi chạy tiến trình QEMU đầy đủ do Libvirt sinh ra, các thông báo lỗi phần cứng giả lập, lỗi BIOS/UEFI, và nguyên nhân crash của VM.

### Thư mục Runtime (`/run/libvirt/qemu/` hoặc `/var/run/libvirt/qemu/`)
Thư mục tạm thời chứa các file phục vụ quá trình máy ảo đang hoạt động (Running). Thư mục này tự động dọn dẹp khi VM tắt.

- `<vm-name>.pid`: Chứa Process ID (PID) của tiến trình QEMU tương ứng đang chạy trên OS Host.

- `<vm-name>.monitor`: File Unix Domain Socket cho phép Libvirt giao tiếp trực tiếp với tiến trình QEMU thông qua giao thức QMP (QEMU Monitor Protocol).

## Các lệnh CLI kiểm tra vị trí và thông tin hệ thống file
Xem danh sách và vị trí file XML của các VM:

```Bash
virsh list --all
ls -la /etc/libvirt/qemu/
```
Xem vị trí các Storage Pool (nơi chứa file đĩa):

```Bash
virsh pool-list
virsh pool-dumpxml default | grep path
```
Đọc log sự cố real-time của một máy ảo:

```Bash
tail -f /var/log/libvirt/qemu/vm1.log
```
Xem Process ID và vị trí file Runtime Socket khi VM đang chạy:
```Bash
ps aux | grep qemu-system
ls -la /run/libvirt/qemu/
```

### Cụm Metadata & Định danh
- `<domain type='kvm'>`: Thẻ gốc khai báo KVM làm Mô đun ảo hóa phần cứng (Hardware Virtualization). Nếu đổi thành type='qemu', máy ảo sẽ chạy chế độ giả lập phần mềm (Software Emulation - rất chậm).
- `<name>`: Tên nhận diện duy nhất của máy ảo trên giao diện CLI (virsh).
- `<uuid>`: Chuỗi định danh 128-bit duy nhất toàn cầu giúp Libvirt phân biệt các máy ảo ngay cả khi trùng tên.
### Cụm Tài nguyên Cốt lõi (CPU & RAM)
- `<memory unit='KiB'>`: Giới hạn dung lượng RAM tối đa máy ảo có thể tiêu tốn trên Host (2097152 KiB = 2GB).
- `<currentMemory>`: Dung lượng RAM được cấp phát thực tế khi VM boot up (dùng phối hợp với cờ Co giãn RAM Ballooning).
- `<vcpu placement='static'>2</vcpu>`: Cấp 2 lõi CPU ảo cho máy ảo.
- `<cpu mode='host-passthrough'>`: Chế độ tối ưu CPU cao nhất. Máy ảo được dùng trực tiếp toàn bộ tập lệnh mở rộng (AVX2, AES-NI, VT-x) từ CPU thật của máy Host.
- `<topology>`: Định nghĩa cấu trúc CPU bên trong VM (1 Socket $\times$ 2 Cores $\times$ 1 Thread).
### 3. Cụm OS, Boot Sequence & Tính năng Nền tảng
- `<type arch='x86_64' machine='pc-q35-8.1'>hvm</type>`: Khai báo kiến trúc x86_64 chạy trên chipset bo mạch chủ Q35 (chuẩn PCIe hiện đại thay thế cho dòng I440FX cũ).
- `<boot dev='hd'/> & <boot dev='cdrom'/>`: Thứ tự ưu tiên khởi động. Hệ thống tra đĩa cứng (hd) trước, nếu không có OS sẽ chuyển sang đĩa quang (cdrom).
- `<features>`: Bật các tính năng phần cứng ảo như `<acpi/>` (giúp Host gửi tín hiệu tắt máy an toàn virsh shutdown) và `<apic/>` (Bộ điều khiển ngắt nâng cao).
- `<on_poweroff>, <on_reboot>, <on_crash>`: Quy định hành vi của Libvirt khi Guest OS tắt, khởi động lại, hoặc bị Panic. destroy nghía là tắt hẳn tiến trình QEMU, restart là bật lại.

### Cụm Thiết bị Lưu trữ (Disks)
- `<driver name='qemu' type='qcow2' cache='none' io='native'/>:type='qcow2'`: Định dạng đĩa ảo cấp phát động, hỗ trợ Snapshot.
- `cache='none' & io='native'`: Bỏ qua bộ nhớ đệm RAM Page Cache của Host để dữ liệu ghi thẳng xuống SSD/HDD vật lý, mang lại hiệu năng I/O tối đa và chống mất dữ liệu khi Host mất điện.
- `<source file='...'/>`: Đường dẫn chứa file đĩa thật trên đĩa đệm Host.
- `<target dev='vda' bus='virtio'/>`:bus='virtio': Sử dụng driver bán ảo hóa (Paravirtualization).
- `dev='vda'`: Tên đĩa trong Linux Guest (/dev/vda).
### Cụm Giao diện Mạng (Network Interfaces)
- `<interface type='network'>`: Khai báo vNIC thuộc quản lý của Libvirt Virtual Network.
- `<mac address='...'/>`: Địa chỉ MAC cố định của card mạng ảo.
- `<source network='default'/>`: Đấu nối card ảo này vào Virtual Switch tên default (Mạng NAT virbr0).
- `<model type='virtio'/>`: Ép dùng driver card mạng bán ảo hóa virtio-net để đạt băng thông tối đa (lên tới 10Gbps+ tùy CPU/RAM).
### Cụm Console, Đồ họa & Kênh giao tiếp
- `<graphics type='vnc' port='-1' autoport='yes'/>`: Bật server VNC ảo, tự động mở một cổng ngẫu nhiên (5900+N) trên IP 127.0.0.1 của Host để truy cập màn hình VM.
- `<console type='pty'>`: Ánh xạ cổng Serial của Guest ra thiết bị ảo Pseudo-Terminal (PTY) của Host, cho phép người dùng điều khiển máy ảo qua dòng lệnh bằng virsh console 
- `<vm>.<channel type='unix'>`: Tạo một kênh truyền socket Unix giữa Host và phần mềm qemu-guest-agent cài bên trong Guest OS (dùng để lấy IP, đổi password, đóng băng đĩa để backup từ ngoài Host).
### Cụm Controller Bus, Tối ưu & Entropy
- `<memballoon model='virtio'/>`: Driver cho phép Host thu hồi RAM rảnh rỗi từ Guest OS hoặc nhồi thêm RAM mà không cần tắt VM.
- `<rng model='virtio'>`: Trích xuất độ nhiễu ngẫu nhiên (Entropy) từ file /dev/urandom của máy Host chuyển vào Guest OS, giúp Guest OS sinh các khóa mã hóa SSH/SSL/TLS cực nhanh mà không bị treo do thiếu Entropy.

## Phân tích file XML của mạng VM
Ví dụ 1 file XML network
```
<network>
  <name>default</name>
  <uuid>65c755f0-61d6-4c9b-b441-0cfd71b7e96e</uuid>
  <forward mode='nat'/>
  <bridge name='virbr0' stp='on' delay='0'/>
  <mac address='52:54:00:7a:45:dd'/>
  <ip address='192.168.122.1' netmask='255.255.255.0'>
    <dhcp>
      <range start='192.168.122.2' end='192.168.122.254'/>
    </dhcp>
  </ip>
</network>
```
### Cụm Metadata & Định danh
- `<name>`: Tên duy nhất của mạng ảo trên Libvirt (dùng trong các lệnh virsh net-*).
- `<uuid>`: Chuỗi định danh 128-bit duy nhất phân biệt giữa các Virtual Network.

### Cụm Chế độ Chuyển tiếp (Forwarding Mode)
Thẻ <forward> quyết định bản chất mô hình mạng:
- `mode='nat'`: Sử dụng iptables/nftables trên Host để làm Source NAT (MASQUERADE). dev='eth0' chỉ định card mạng thật mà gói tin sẽ đi ra Internet.
- `mode='route'`: Chuyển tiếp Layer 3 thuần túy (không biến đổi IP). Yêu cầu Router ngoài mạng thật phải có static route trỏ ngược về Host.
- `mode='bridge'`: Đấu nối trực tiếp vào một Linux Bridge vật lý có sẵn trên Host.

KHÔNG CÓ THẺ <forward>: Mạng tự động biến thành Isolated Mode (Host-Only), gói tin bị chặn hoàn toàn không thể ra ngoài Host.

### Cụm Switch ảo Layer 2 (Bridge & MAC)
- `<bridge name='virbr2'/>`: Tên của giao diện Bridge ảo được Kernel Host khởi tạo (hiển thị trong lệnh ip a hoặc brctl show).
- `stp='on'`: Bật Spanning Tree Protocol để chống hiện tượng lặp vòng mạng Layer 2 (Network Loop).
- `delay='0'`: Thời gian chờ chuyển trạng thái cổng (Forward Delay) đặt bằng 0 giây giúp vNIC của VM có mạng ngay lập tức khi vừa boot up.
- `<mac address='...'/>`: Địa chỉ MAC ảo của chính giao diện Bridge (virbr2) trên máy Host.

### Cụm Địa chỉ IP Gateway & Dịch vụ DHCP
- `<ip address='192.168.150.1' netmask='255.255.255.0'>`: Thiết lập IP cho giao diện Bridge trên Host. Đây đóng vai trò là Default Gateway cho tất cả máy ảo nối vào mạng này.

- `<dhcp>`: Ra lệnh cho Libvirt khởi chạy một tiến trình dnsmasq riêng biệt để lắng nghe và cấp phát IP tự động.

- `<range start='...' end='...'/>`: Giới hạn dải IP cấp phát động.

- `<host mac='...' name='...' ip='...'/>` (Static Lease): Kỹ thuật MAC Binding. Mỗi khi VM có MAC này xin IP, dnsmasq luôn trả về đúng IP `192.168.150.50`, giúp VM có IP cố định mà không cần cấu hình tĩnh bên trong Guest OS.

### Cụm Tên miền & Dịch vụ DNS Nội bộ
- `<domain name='lab.local' localOnly='yes'/>`: Tự động gán đuôi Domain cho các VM. 
- `localOnly='yes'` báo cho dnsmasq chỉ phân giải tên miền này nội bộ, không forward truy vấn `.lab`, `.local` ra DNS Server ngoài Internet.

- `<dns>`: Khai báo các bản ghi A/CNAME/TXT tĩnh trực tiếp để các VM trong mạng có thể phân giải tên miền của nhau hoặc phân giải về IP Gateway.

### Cụm Quản lý Băng thông & QoS (Tùy chọn)
- `<bandwidth>`: Áp dụng Traffic Shaping (dùng tc - Traffic Control của Linux) lên toàn bộ Switch ảo.

- `inbound / outbound`: Giới hạn tốc độ Tải xuống / Tải lên (đơn vị: KiB/s). average là tốc độ trung bình, peak là tốc độ xả tối đa, burst là dung lượng cho phép vượt ngưỡng trong thời gian ngắn.

## Tạo máy ảo và mạng sử dụng XML
### Tạo mạng sử dụng XML
Tạo file định nghĩa mạng
```
cat <<EOF > lab-network.xml
<network>
  <name>lab-net</name>
  <forward mode='nat'/>
  <bridge name='virbr10' stp='on' delay='0'/>
  <ip address='192.168.100.1' netmask='255.255.255.0'>
    <dhcp>
      <range start='192.168.100.10' end='192.168.100.100'/>
    </dhcp>
  </ip>
</network>
EOF
```
Kiểm tra
```
# Nạp cấu hình XML vào KVM
root@MANHLAB1:~# virsh net-define lab-network.xml
Network lab-net defined from lab-network.xml

# Bật mạng
root@MANHLAB1:~# virsh net-start lab-net
Network lab-net started

# Cho phép mạng tự khởi động vào OS
root@MANHLAB1:~# virsh net-autostart lab-net
Network lab-net marked as autostarted

# Kiểm tra trạng thái và giao diện Bridge vừa tạo
root@MANHLAB1:~# virsh net-list --all
 Name      State    Autostart   Persistent
--------------------------------------------

 lab-net   active   yes         yes

root@MANHLAB1:~# ip a show virbr10

    inet 192.168.100.1/24 brd 192.168.100.255 scope global virbr10
```

Khai báo và khởi động máy ảo
```
root@MANHLAB1:~# virsh define demo-vm.xml
Domain 'demo-vm' defined from demo-vm.xml

root@MANHLAB1:~# virsh start demo-vm
Domain 'demo-vm' started
```
Kiểm tra danh sách máy ảo
```
root@MANHLAB1:~# virsh list --all
 Id   Name      State
-------------------------
 6    vm2       running
 7    vm1       running
 8    demo-vm   running
```
