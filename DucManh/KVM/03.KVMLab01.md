## Kiểm tra tính năng ảo hóa lồng
Do hệ điều hành Ubuntu của tôi đang chạy trên một máy ảo, phải đảm bảo phần mềm quản lý máy ảo gốc (VMware, VirtualBox, Proxmox...) đã bật tính năng ảo hóa phần cứng cho Ubuntu.

Chạy lệnh kiểm tra trên Ubuntu:
```
egrep -c '(vmx|svm)' /proc/cpuinfo
```
- Kết quả > 0: Máy ảo Ubuntu đã nhận được tính năng ảo hóa phần cứng (sẵn sàng cài KVM).
- Kết quả = 0: Bạn cần tắt máy ảo Ubuntu, mở cài đặt của phần mềm ảo hóa gốc và tích chọn "Virtualize Intel VT-x/AMD-V" (VMware) hoặc "Enable Nested VT-x/AMD-V" (VirtualBox), sau đó bật lại Ubuntu.

Ví dụ:

```
root@MANHLAB1:~# egrep -c '(vmx|svm)' /proc/cpuinfo
0
```
Nghĩa là máy ảo đang không nhận được tính năng ảo hóa phần cứng. Lúc này, nếu bạn sử dụng phần mềm quản lý máy ảo vSphere thì bạn có thể làm như sau để thực hiện bật
- Truy cập vào trang quản trị
- Thực hiện tắt máy ảo
- Vào cài đặt máy ảo
- Tìm mục **CPU** và tích chọn vào ô **Expose hardware assisted virtualization to the guest OS**

![](/DucManh/Image/image5.png)

Kiểm tra lại:
```
root@MANHLAB1:~# egrep -c '(vmx|svm)' /proc/cpuinfo
4
```
Máy ảo Ubuntu của bạn hiện có 4 vCPU (hoặc 4 core/thread). Cả 4 vCPU này đều đã nhận diện được tập lệnh ảo hóa phần cứng (vmx của Intel hoặc svm của AMD) do vSphere chuyển tiếp xuống.

## Cài đặt KVM
Sử dụng câu lệnh sau:

```bash
sudo apt -y install bridge-utils cpu-checker libvirt-clients virtinst virt-manager libvirt-daemon-system qemu-system-x86 qemu-utils qemu-kvm
```
Các gói đã cài:
- `bridge-utils`: Công cụ tạo và quản lý các giao diện mạng ảo dạng Bridge (như br0), cho phép máy ảo kết nối trực tiếp vào dải mạng vật lý của máy Host.
- `cpu-checker`: Cung cấp lệnh kvm-ok để kiểm tra xem CPU máy vật lý/máy chủ có bật tính năng ảo hóa phần cứng (Intel VT-x hoặc AMD-V) hay chưa.
- `libvirt-clients`: Cung cấp các công cụ dòng lệnh (CLI) phía client để điều khiển máy ảo, nổi bật nhất là lệnh virsh.
- `virtinst`: Cung cấp các lệnh khởi tạo và thao tác máy ảo từ CLI, bao gồm virt-install (dùng để tạo VM mới) và virt-clone.
- `virt-manager`: Phần mềm giao diện đồ họa (GUI) giúp quản lý, tạo, theo dõi máy ảo trực quan thay vì dùng dòng lệnh.
- `libvirt-daemon-system`: Chứa daemon dịch vụ nền libvirtd và các file cấu hình hệ thống. Đây là trung tâm quản lý giao tiếp giữa các công cụ điều khiển (virsh, virt-manager) với Hypervisor (QEMU/KVM).
- `qemu-system-x86`: Chứa bộ phần mềm QEMU đóng vai trò giả lập các thành phần phần cứng (RAM, đĩa, NIC, chipset) dành cho kiến trúc x86 và x86_64.
- `qemu-utils`: Bộ công cụ xử lý file đĩa ảo, chứa lệnh quan trọng qemu-img để tạo đĩa, chuyển đổi định dạng đĩa (raw $\leftrightarrow$ qcow2), mở rộng dung lượng đĩa ảo.
- `qemu-kvm`: Gói tích hợp (meta-package) đảm bảo QEMU kích hoạt và sử dụng mô-đun tăng tốc phần cứng KVM Kernel Module (kvm.ko) thay vì chỉ giả lập bằng phần mềm thuần túy.

Nếu kết quả hiện như sau nghĩa là cài đặt thành công
```bash
root@MANHLAB1:~# kvm-ok
INFO: /dev/kvm exists
KVM acceleration can be used
```

## Khởi chạy KVM
Chúng ta sử dụng `libvirtd` để thao tác với KVM. Khởi chạy libvirtd:
```bash
sudo systemctl enable --now libvirtd
```
## Cấp quyền sử dụng KVM cho user
```bash
sudo adduser $USER libvirt
sudo adduser $USER kvm
```

## Thực hành tạo máy ảo
### Tải các file hệ điều hành phù hợp
Vì là bài lab, tôi sẽ test thử bằng hệ điều hành aplinelinux
```bash
# Tạo thư mục chứa ISO trong không gian của Libvirt
sudo mkdir -p /var/lib/libvirt/boot-iso

# Tải file ISO Alpine Linux (~200MB)
sudo wget -P /var/lib/libvirt/boot-iso/ https://dl-cdn.alpinelinux.org/alpine/v3.20/releases/x86_64/alpine-virt-3.20.3-x86_64.iso
```
### Tạo ổ cứng cho VM
Thực hiện tạo riêng file đĩa .qcow2 cho 2 máy ảo
```bash
# Tạo ổ đĩa ảo cho VM1
root@MANHLAB1:~# sudo qemu-img create -f qcow2 /var/lib/libvirt/images/vm1.qcow2 6G
Formatting '/var/lib/libvirt/images/vm1.qcow2', fmt=qcow2 cluster_size=65536 extended_l2=off compression_type=zlib size=6442450944 lazy_refcounts=off refcount_bits=16

# Tạo ổ đĩa ảo cho VM 2
root@MANHLAB1:~# sudo qemu-img create -f qcow2 /var/lib/libvirt/images/vm2.qcow2 6G
Formatting '/var/lib/libvirt/images/vm2.qcow2', fmt=qcow2 cluster_size=65536 extended_l2=off compression_type=zlib size=6442450944 lazy_refcounts=off refcount_bits=16
```

Giải thích câu lệnh:
- `qemu-img`: sử dụng công cụ qemu-img
- `create`: hành động khởi tạo
- `-f`: flag để ám chỉ khởi tạo ổ đĩa ảo dạng qcow2
- `/var/lib/libvirt/images/vm1.qcow2`: thư mục chứa
- `6G`: Dung lượng 6G

Đây là minh chứng rõ nhất cho cơ chế Thin Provisioning của định dạng qcow2:
- `virtual size`: 6 GiB: Dung lượng không gian ảo mà máy ảo (VM) nhìn thấy và có thể sử dụng tối đa.
- `disk size`: 196 KiB: Dung lượng thực tế file .qcow2 này đang chiếm trên ổ đĩa 30GB của máy Host. Ban đầu nó chỉ tốn vài trăm KB để lưu các thông tin quản lý (header/metadata), khi nào máy ảo ghi dữ liệu thật thì file này mới tự động nở ra.
- `cluster_size`: 65536: Kích thước mỗi khối (Block) dữ liệu là 64 KiB. KVM sẽ cấp phát đĩa thực tế theo từng khối 64 KiB này mỗi khi máy ảo ghi dữ liệu mới.
- `compat: 1.1`: Chuẩn định dạng QCOW2 hiện đại (hỗ trợ tính năng Snapshot, mã hóa và tối ưu hiệu năng).

### Tạo VM1 bằng CLI
Sử dụng đoạn mã sau:
```bash
sudo virt-install \
  --name vm1 \
  --ram 1024 \
  --vcpus 1 \
  --disk path=/var/lib/libvirt/images/vm1.qcow2,format=qcow2 \
  --os-variant generic \
  --network network=default \
  --cdrom /var/lib/libvirt/boot-iso/alpine-virt-3.20.3-x86_64.iso \
  --graphics vnc,listen=0.0.0.0 --noautoconsole
```
Giải thích từng tham số:
- `sudo virt-install`: Lệnh của Libvirt dùng để khởi tạo và đăng ký một máy ảo mới vào hệ thống KVM/QEMU.
- `--name vm1`: Đặt tên định danh cho máy ảo là vm1. Tên này được dùng khi quản lý bằng các lệnh virsh hoặc hiển thị trên virt-manager.
- `--ram 1024`: Cấp phát 1024 MB (1 GB) dung lượng RAM ảo (vRAM) cho máy ảo từ RAM vật lý của máy Host.
- `--vcpus 1`: Phân bổ 1 lõi vi xử lý ảo (1 vCPU) cho máy ảo.
- `--disk path=/var/lib/libvirt/images/vm1.qcow2,format=qcow2`: Chỉ định máy ảo sử dụng file đĩa vm1.qcow2 (đã tạo thủ công bằng qemu-img trước đó) làm ổ cứng chính.
- `format=qcow2`: Khai báo chuẩn định dạng đĩa đệm động (Thin Provisioning).
- `--os-variant generic`: Khai báo cấu hình tối ưu của hệ điều hành. Dùng generic khi cài các hệ điều hành nhẹ hoặc không có trong danh sách nhận diện mặc định của Libvirt (như Alpine Linux).
- `--network network=default`: Gắn card mạng ảo của VM vào Switch ảo mặc định (virbr0) của KVM. Chế độ này dùng NAT, giúp máy ảo tự động nhận IP nội bộ từ KVM và có thể truy cập Internet.
- `--cdrom /var/lib/libvirt/boot-iso/alpine-virt-3.20.3-x86_64.iso`: Gắn file ISO bộ cài Alpine Linux vào ổ đĩa CD-ROM ảo để máy ảo đọc và boot hệ điều hành khi khởi động lần đầu.
- `--graphics vnc,listen=0.0.0.0`: Bật giao diện hiển thị ảo VNC, mở cổng kết nối trên mọi địa chỉ IP (0.0.0.0) để cho phép kết nối xem màn hình máy ảo từ xa bằng các công cụ VNC Viewer.
- `--noautoconsole`: Yêu cầu lệnh thực thi xong sẽ trả lại quyền điều khiển cho Terminal ngay lập tức, không tự động bật cửa sổ màn hình máy ảo (Console).

Cơ chế xử lý ngầm bên dưới:
- Sinh cấu hình XML: virt-install tự động dịch toàn bộ các tham số trên thành một file cấu hình XML chuẩn của Libvirt và lưu vào /etc/libvirt/qemu/vm1.xml.
- Kích hoạt tiến trình QEMU: Dịch vụ libvirtd tiếp nhận file XML, gọi tiến trình qemu-system-x86_64 chạy ngầm.
- Thực thi qua KVM: KVM Kernel module cấp phát vCPU/RAM và đưa VM vào trạng thái khởi động từ đĩa CD-ROM (file ISO Alpine).

### Tạo VM2 bằng Virt-Manager
Bây giờ bạn thao tác trên cửa sổ Virtual Machine Manager để tạo vm2:
- Bấm vào biểu tượng Tạo máy ảo mới (hình màn hình máy tính có ngôi sao vàng ở góc trên bên trái).
- Step 1: Chọn Local install media (ISO image or CDROM) $\rightarrow$ Bấm Forward.
- Step 2: Bấm Browse... $\rightarrow$ chọn Browse Local (ở góc dưới).Tìm chọn file ISO: `/var/lib/libvirt/boot-iso/alpine-virt-3.20.3-x86_64.iso` $\rightarrow$ Bấm Open.Bỏ tích chọn Automatically detect, gõ chọn ***Generic Linux*** ở ô tìm kiếm $\rightarrow$ Bấm Forward.
- Step 3: Memory: 1024 MiB.CPUs: 1 $\rightarrow$ Bấm Forward.
- Step 4 (Gắn đĩa vm2.qcow2 đã tạo bằng qemu-img):Tích chọn ***Select or create custom storage*** $\rightarrow$ Bấm ***Manage..***. Bấm ***Browse Local*** $\rightarrow$ Tìm chọn file `/var/lib/libvirt/images/vm2.qcow2` $\rightarrow$ Bấm Open $\rightarrow$ Bấm Forward.
- Step 5:Name: Đặt tên `vm2`. Network selection: Để mặc định Virtual network 'default' : NAT.Bấm Finish.

```Bash

```
Tạm dừng máy ảo (Freeze vào RAM) / Tiếp tục chạy:

```Bash

virsh autostart --disable vm1   # Tắt tự động
```
### Tạo và thao tác với snapshot
Chức năng tạo snapshot chỉ hỗ trợ khi sử dụng ổ đĩa dạng `qcow2`. Vì vậy nếu của bạn đang là định dạng `raw` thì bạn phải chuyển sang dạng `qcow2` để có thể tạo snapshot.

Ví dụ
```
root@MANHLAB1:~# virsh snapshot-create-as --domain vm1 \
  --name snap1_clean_state \
  --description "Snapshot sau khi da cau hinh mang"
Domain snapshot snap1_clean_state created
```
*Lưu ý:* Nếu máy ảo đang chạy, KVM sẽ chụp cả trạng thái RAM (Live snapshot). Nếu máy ảo đang tắt, KVM chỉ chụp trạng thái ổ đĩa.

Liệt kê tất cả snapshot của vm1:

```Bash
root@MANHLAB1:~# virsh snapshot-list vm1
 Name                Creation Time               State
----------------------------------------------------------
 snap1_clean_state   2026-10-29 09:48:00 +0700   running

```
Xem chi tiết thông số của 1 snapshot:

```Bash
root@MANHLAB1:~# virsh snapshot-list vm1
 Name                Creation Time               State
----------------------------------------------------------
 snap1_clean_state   2026-10-29 09:48:00 +0700   running

root@MANHLAB1:~# virsh snapshot-info --domain vm1 --snapshotname snap1_clean_state
Name:           snap1_clean_state
Domain:         vm1
Current:        yes
State:          running
Location:       internal
Parent:         -
Children:       0
Descendants:    0
Metadata:       yes
```
Xem snapshot hiện tại VM đang sử dụng (Current Snapshot):

```Bash
root@MANHLAB1:~# virsh snapshot-current vm1 --name
snap1_clean_state
```
Revert để chạy lại một bản snapshot đã tạo
```bash
root@MANHLAB1:~# virsh snapshot-revert vm1 snap1_clean_state
Domain snapshot snap1_clean_state reverted
```
Xóa 1 bản snapshot
```bash
root@MANHLAB1:~# virsh snapshot-delete --domain vm1 --snapshotname snap1_clean_state
Domain snapshot snap1_clean_state deleted
```
